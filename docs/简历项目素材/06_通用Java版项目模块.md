## 简历精简稿

**项目一：AgentCV — AI简历工作台**

独立开发（AI辅助编码）｜Java 17 · Spring Boot 3.5 · Spring JDBC · PostgreSQL 17 · Flyway · DeepSeek API

**简介：** 面向使用大模型反复修改简历时资料分散、背景重复解释与多稿混淆的问题，构建支持资料复用、背景沉淀和独立稿件维护的AI工作台。

- **资料复用与独立稿件：** 围绕同一人物维护不同目标简历，设计“人物档案—工作区”模型，材料按需多区引用、稿件复制后独立编辑；将资料共享与稿件修改分离，避免重复建档和相互覆盖。
- **可控背景沉淀：** 为减少经历重复解释并控制模型无依据扩写，设计“AI提炼—用户确认—持久复用”流程；分离参考材料、候选与有效背景，按确切正文和版本确认，支持纠正、撤回，AI建议由用户决定是否采纳。
- **并发与依据一致性：** 针对多页提交和资料更新引发的冲突，结合行锁、版本校验与幂等指纹拒绝重复写入和过期覆盖；受理时固定资料快照，变更后标识旧依据，后续请求使用最新资料。
- **外部调用可靠性：** 针对网络异常与落库失败可能诱发重复调用，采用持久请求、有界受理及单线程调度，短事务分离模型执行与结果保存；保存失败仅重试落库，可能已外发的未知请求不自动重调。

**个人职责（版面允许时保留）：** 制定开发计划，组织AI编码工具按纵向切片实现，并以用户视角验收功能与交互。

## 工程机制底稿（面试展开）

最新正文采用“两条产品设计＋两条后端工程”的组合，以下保留原五条技术稿的完整逻辑与验证边界。验证均引自既有记录，本次不重跑业务测试。

### A. 并发与幂等：对应原第1条

- **发现问题：** 多页操作、重复点击、提交响应丢失可能重复受理；旧页面可能覆盖新状态，资料与回答不能跨人物/工作区串用。
- **根因分析：** 前端按钮防重无法协调多页；未收到响应不等于后端未受理。单线程执行不能替代数据库受理检查，幂等不能替代版本冲突检测。
- **方案取舍：** 单操作者、单实例场景采用数据库任务与单线程调度，不引入MQ或多实例租约；全局上限控制积压，不作吞吐承诺。
- **关键实现：** send短事务获取全局事务级advisory lock及工作区/人物行锁，检查请求键与指纹、对话版本、资料范围、同区活动请求、全局上限，原子保存用户消息/请求/快照。后台通过FOR UPDATE SKIP LOCKED领取ACCEPTED并提交CALLING，事务外调用模型。归属校验、材料复合外键、版本条件和唯一约束分别约束跨人物关联、过期覆盖及重复写入，不构成严格全局FIFO保证。
- **验证方式：** S01两页冲突与幂等回放；S03跨人物引用拒绝；S04同键同请求、同区第二次拒绝及模型计数；S08第5项受理拒绝且保留草稿。
- **结果/边界：** 已覆盖路径按规则处理；默认4项包含ACCEPTED、CALLING或SAVE_FAILED，执行线程仅1个。未提供多实例协调、负载或吞吐优化证据。
- **实现入口：** [ConversationService.send/tick](../../src/main/java/com/agentcv/conversation/ConversationService.java)、[WorkspaceService.write](../../src/main/java/com/agentcv/workspace/WorkspaceService.java)。

### B. 确认写入：对应原第2条

- **发现问题：** 模型提炼不应直接成为有效背景；用户曾按系统提示回复“确认保存全部”却重新提炼，部分确认与重试也必须对应原意。
- **根因分析：** 初版前后端重复解析确认，后台漏提示原句；生成、展示、确认与写库不是同一动作，候选变化后旧确认不能沿用。
- **方案取舍：** 模型只形成候选，后台有限语法与明确按钮解释确认，不再调用模型判断写入授权；候选/确认/背景分表。用户确认不是外部真实性认证。
- **关键实现：** 绑定人物、工作区、候选版本、展示正文、上下文代次和选择项，仅保存对应部分。operation按作用域+键记录指纹/响应，同键同载荷回放，同键异载荷拒绝；失败回滚后原键重试。候选已有确认及选择项也用于防重复，过期候选/代次拒绝新写入。已完成操作回放只返回原结果，不重新执行候选时效检查。
- **验证方式：** S06两项原句确认、部分确认、否定/假设/未展示内容拒绝、重复键及新键重复确认；数据库故障回滚重试且模型计数不增；浏览器fixture覆盖提示原句和503重试。
- **结果/边界：** 已覆盖表达可确切落库，重试无需模型；有限确认语法不是通用语义识别，不宣称消除幻觉或完整真实模型验收。
- **实现入口：** [BackgroundService.confirm/selection](../../src/main/java/com/agentcv/background/BackgroundService.java)、[WorkspaceService.write](../../src/main/java/com/agentcv/workspace/WorkspaceService.java)。

### C. 请求快照与版本：对应原第3条

- **发现问题：** 资料在回答中更新后，最新界面与模型实际输入不同；历史聊天仍可能含撤回背景，旧页面也可能把已清空草稿重新写回。
- **根因分析：** 异步调用与编辑不同步，历史和当前有效资料并非同一数据域；界面更新不能改变已外发内容。
- **方案取舍：** 固定受理输入、另存依据版本，保留旧回答但提示，不自动重答；后续用新资料及变更说明，不承诺撤回外发或语义遗忘。
- **关键实现：** 快照固定简历开关、选定材料/解析限制、同人物全部有效背景与预算内近期完整问答，basis_json保存版本。必需资料超192 KiB本地字节预算则拒绝，历史按完整问答选择，不做摘要或向量检索。分隔更新对话版本/epoch及历史边界，保留旧消息；清空另删除本区消息、清草稿/请求正文，保留必要幂等凭证。后端草稿检查版本/epoch，前端检测代次变化后保留输入并暂停保存。分隔不清除仍选材料与有效背景。
- **验证方式：** S04截获输入证明未选材料排除；S05分隔前消息不发、清空与旧草稿保护；S07延迟请求中改背景，核对原快照、旧依据提示及下次输入；S09追加POST正文为点击时文字，避免异步检查误读新草稿。
- **结果/边界：** 已覆盖路径区分实际输入和当前资料；变更说明不是保证所有语义冲突都正确处理，也不是完整提示注入防御。
- **实现入口：** [ConversationService.buildInput/basisChanged](../../src/main/java/com/agentcv/conversation/ConversationService.java)、[ConversationStateService](../../src/main/java/com/agentcv/conversation/ConversationStateService.java)、[前端对话](../../frontend/src/conversation.ts)。

### D. 分阶段恢复：对应原第4条与启动保护

- **发现问题：** 网络异常后不知供应商是否执行；模型返回但落库失败时重生成会重复收费；重启后不能盲目接管已外发任务。
- **根因分析：** HTTP与数据库不能原子提交，生成成功、记录保存成功和结果未知必须分开。
- **方案取舍：** 可能外发窗口保守处理，不追求供应商端恰好一次；数据库保存任务，当前进程暂存回答，未知后由用户决定新调用。
- **关键实现：** 受理/领取/保存分别短事务，HTTP等待不占数据库长事务；返回先放unsaved，再写回答/候选/状态。SAVE_FAILED只重试已有结果并阻塞本区新发送。启动先持WorkerGuard文件锁再恢复：遗留CALLING置UNKNOWN，内存回答重启丢失标明原因，ACCEPTED保留待领取。停止中断并等待旧执行，未退出则锁保留到进程结束。文件锁本身不恢复结果。
- **验证方式：** S04数据库CHECK注入保存失败，回答仍可查询，重试不增模型计数；S08随机schema独立JAR状态构造、强杀重启、跨进程锁实验；S09串联回归。
- **结果/边界：** 被测故障按阶段处理，不自动重调可能外发请求；暂存不是持久结果缓存，重启可能丢回答。同机同锁路径协调不等于多实例高可用，未覆盖全部精确崩溃窗口。
- **实现入口：** [ConversationService.persist/retryPersist/start](../../src/main/java/com/agentcv/conversation/ConversationService.java)、[RequestRecovery](../../src/main/java/com/agentcv/conversation/RequestRecovery.java)、[WorkerGuard](../../src/main/java/com/agentcv/conversation/WorkerGuard.java)。

### E. 完整响应与迟到防护：对应原第5条

- **发现问题：** 用户反馈偶发数分钟等待、无法停止，原超时没有覆盖响应头之后的正文读取。
- **根因分析：** ofInputStream在响应头后完成future，后续readNBytes不受同一期限保护；本地中断不能证明供应商取消，结果可能迟到。
- **方案取舍：** 完整正文接收future限时，不自动重试或换模型；停止仅结束本地等待并放弃迟到结果，保留可能收费边界。
- **关键实现：** sendAsync配合pending.get限时等待，失败取消future；接收中按累计大小限制内存。stopWaiting短事务锁区转已确认风险UNKNOWN，再中断线程；持久化/失败更新要求仍为CALLING，旧结果不得新增回答或背景。
- **参数更新：** 最新代码核对为连接15秒、完整响应默认180秒且可配置、接收上限2 MiB。旧记录及事实库的60秒是历史参数；简历不写数值。默认值不代表已检查运行进程的实际配置覆盖，期限也不包含排队。
- **验证方式：** S06本地HTTP先发头和空格再阻塞正文，800ms测试期限下3秒内退出且1次请求；阻塞替身覆盖停止后旧结果不落库。2 MiB专项故障测试原记录仍缺，本轮未补跑。
- **结果/边界：** 被测路径正文等待有界、停止后拒绝迟到结果；不保证供应商取消、不收费或在期限内成功。
- **实现入口：** [DeepSeekGateway](../../src/main/java/com/agentcv/model/DeepSeekGateway.java)、[ConversationService.stopWaiting](../../src/main/java/com/agentcv/conversation/ConversationService.java)、[DeepSeekDeadlineTest](../../src/test/java/com/agentcv/model/DeepSeekDeadlineTest.java)。

## 产品设计底稿：从用户需求到后端机制

本节依据[需求分析](../阶段设计/01_需求分析.md)§1—4、§6，以及[产品设计](../阶段设计/02_产品设计.md)§1、§3—5；实现和验证来源仍为S01—S09，不将设计目标当成已证明的降本结果。

### 1. 为什么资料共享，但稿件不联动

- **用户需求：** 同一个人维护Java与AI等不同目标简历，需要复用经历材料，又不希望改一份稿件影响另一份。
- **设计决定：** 人物档案保存共用资料，工作区承载独立目标稿件；材料通过关系按需供多个工作区参考，复制仅形成独立简历，不复制聊天和材料关系。
- **取舍理由：** 共享的是参考材料和有效背景，稿件是用户面向目标岗位的表达成果，二者不应自动联动。没有引入复杂版本树、自动合并或批量派生。
- **后端承接：** profile/workspace归属、材料关系复合外键、来源/目标版本校验、独立简历修订；复制源和目标按固定顺序锁定，过期预览拒绝复制。
- **可说的结果：** 已实现同人资料按需复用、复制后独立编辑；S02/S03/S09记录相关测试与体验。减少重复整理是设计目标，未有时间成本对照，不写效率提升。

### 2. 为什么确认背景，而不把整份材料当事实

- **用户需求：** 经历在不同任务中反复解释，同时AI可能扩大职责或加入无依据成果，用户需要核查并纠正。
- **设计决定：** 材料作为可编辑参考文档，不要求整份认证；AI提炼具体候选，用户核对确切内容与用途后才沉淀为背景，同人物跨区复用，可纠正/撤回。
- **取舍理由：** 自动保存推断会污染后续输入，强制逐份认证又增加操作负担；以具体陈述为确认粒度，确认部分只保存部分。用户确认不等于外部真实性认证。
- **后端承接：** 候选/确认/背景分表、版本/展示正文/代次绑定、事务与幂等确认；有效背景和普通聊天分开，模型无直接写有效背景的权限。
- **可说的结果：** 已实现明确确认、部分保存、跨区复用及纠正撤回；S06/S07/S09保留验证范围。不能宣称消除幻觉、避免所有扩写或普遍减少返工。

### 3. 为什么AI给建议，而不直接改简历

- **用户需求：** 用户需要对建议依据和职责表达作判断，改写请求不等于授权覆盖已保存稿件。
- **设计决定：** 对话结合当前允许资料提供建议，用户自行采纳并保存；参考简历时先保存再发送，失败不分析服务端旧稿。工作区保存已成功的对话与输入草稿，支持重开继续。
- **后端承接：** 简历/对话/草稿独立对象、版本条件与请求快照，查询原请求而非刷新重发；上下文分隔和记录清空分别处理。
- **可说的结果：** 保留用户的采用决定权与成果保存状态，支持持续交流；不写AI自动写回、正式导出或完整任务自动化。减少手工搬运仍是目标，当前采用建议需要手动编辑。
