# AgentCV 需求分析（审阅稿）

> 本文说明用户是谁、问题是什么、希望达到什么目标，以及产品需求与业务边界。功能清单、优先级和 MVP 范围见[产品设计](02_产品设计.md)；本文不安排版本、开发顺序或实现任务。

## 1. 用户与使用场景

面向**已有中文简历，需要反复修改并维护不同求职目标简历的人**。

使用范围为项目负责人自用与面试演示，由一个操作者使用。可以为不同人整理资料，但不同人物的材料与简历必须分开，不向其他人开放独立账号。

典型场景：用户已有一份后端简历，希望维护另一份侧重 AI 应用的简历。两份简历需要独立修改，又希望复用同一个人的相关资料，减少重复整理和解释。

## 2. 核心问题

使用网页版模型修改简历时，用户不仅要等待生成内容，还要准备资料、反复解释、核查结果，再把修改搬回简历。主要负担是：

| 痛点 | 希望减少的负担 |
| --- | --- |
| 材料分散，不同目标下需要重复查找和说明背景 | 整理资料与重复输入的时间、操作成本 |
| 已经解释清楚的经历在后续任务中仍被反复询问 | 重复核对与重新讲述个人背景的成本 |
| 改写可能加强职责或加入无依据内容，需要来回核对与纠正 | 核查、追问和返工成本 |
| 在聊天结果与简历之间复制、合并修改，容易混淆不同稿件 | 手工搬运、版本辨认和误覆盖后的返工成本 |

这些负担来自用户需求及历史任务观察；历史材料出现过无依据扩写，但不足以说明普遍发生频率或总体错误率。

## 3. 目标与价值判断

**以降本为主**：相较网页版模型修改简历，降低用户完成同类任务的时间成本、操作成本和经济成本。提升改写效果是次要目标，不以“比强模型写得更好”作为产品成立的前提。

产品应让用户围绕同一个人的材料，持续维护不同目标的独立简历；需要帮助时能够提出修改需求、补充信息、核对建议，再自行决定如何调整。

价值通过同类任务对照判断：总耗时、手工操作、返工和实际经济支出。费用比较应同时考虑网页版模型的实际费用及本产品使用外部服务的费用；**收益待验证，不预设一定更省钱或更省时**。

## 4. 核心用户需求

一个人的资料集合称为个人档案，一份独立目标简历所在的使用空间称为工作区。以下描述用户需要解决的事情，不划分版本或优先级。

本文统一称工作区中可编辑保存的简历为“工作区简历”。“导入工作区简历”与“添加个人材料”是两种独立用途，不自动互相加入；同一人物的一份个人材料可由用户选择供多个工作区参考。

| 用户需要 | 期望结果 |
| --- | --- |
| 集中整理并复用个人材料 | 同一个人的简历、项目说明等资料可持续使用，减少重复查找和解释；不同人物的资料不混用 |
| 沉淀已明确确认的个人背景 | AI 提炼具体经历，用户核对并同意保存后可持续复用；能够查看、纠正和撤回，不必在不同任务中重复解释 |
| 维护不同目标的简历 | 同一个人可维护多份独立简历，包括同方向不同侧重点的稿件；修改一份不覆盖另一份 |
| 使用已有中文材料 | 材料内容可读、可检查、可修正；用户知道哪些内容可用，不能读取或可能遗漏时得到明确告知 |
| 控制资料的使用范围 | 用户知道哪些材料用于哪份简历的分析，并能决定使用或停止使用，不因材料已保存就默认参与分析 |
| 辨认资料的新旧与适用性 | 用户能够了解资料的时间信息，发现内容不再适用时停止参考，避免历史信息被当作当前情况；不要求仅因长期未使用就反复确认所有材料 |
| 获得 AI 辅助并核查结果 | 能用自然语言提出任务、补充信息、核对建议的依据与未知，再决定是否调整简历；AI 辅助不是可选的附加价值 |
| 继续尚未完成的交流 | 重新进入工作区能够回看讨论并继续，不必重新解释任务进展；用户可以选择不再携带旧聊天，而不必删除可回看的记录 |
| 持续维护并保留成果 | 能继续修改已保存简历并重新打开使用，减少聊天结果与工作区简历之间的搬运；失败时不误以为成果已保存 |

## 5. 项目非目标

- 不做多用户协作或客户管理平台，不替用户探索或选择职业。
- 不认证经历真实性，不保证录用，也不保证发现所有问题。
- 不以完整聊天历史检索为产品目标。
- 不以完美还原原文件视觉排版为目标。

具体支持格式、功能取舍与基础 MVP 的包含及排除项统一记录在产品设计中，不在这里重复维护。

## 6. 业务边界

- 用户决定使用哪些材料、是否发起分析及是否采用修改；请求改写不等于同意改变工作区简历。
- 材料是参考文档，不要求整份核实，也不以逐份人工检查确认作为正常使用的前提；提取错误和遗漏须可辨认、可修正，解析失败不能冒充可读。
- 用户已确认背景与简历自述、参考材料、模型推测分开。只有展示具体内容及保存用途并取得明确确认后，才保存对应背景；确认局部不代表认可整份材料，不扩大职责、数字或成果。
- 背景按人物持久保存，独立于材料，可跨同人工作区复用；对话中可查看、纠正和撤回。新信息冲突时先澄清，不静默覆盖；用户确认不等于外部真实性核验。
- 当前人物的全部已确认背景用于 AI 对话，不做相关性筛选；须明确用途和外发范围，不跨人物，不静默遗漏后声称使用全部背景。
- 资料不因时间经过自动失效，不强制定期重新确认。材料变化不自动删除独立确认的背景，背景变化不自动改写材料或简历。
- 材料只使用当前工作区明确选定的范围，选定后沿用，不要求每条消息重新选择；导入不自动开放给 AI。停止读取与排除既有对话信息不同，不能承诺撤销已外发内容。
- 材料或背景变化不自动改变已保存的工作区简历；工作区简历、候选建议和保存结果应让用户分得清。
- 失败不能冒充成功；未保存内容应受到保护，并可复制留存。
- 对话记录、未发送输入和已确认背景是不同内容：保存聊天不等于确认事实，保存输入不等于发送给模型；不把保留的全部聊天冒充模型始终记得的上下文。
- 仅限本人本机或受保护的局域环境使用，不开放公网。模型接收方及使用范围须清楚可见，由用户选择资料并主动发送，不另设外发授权勾选或确认弹窗；不能静默换接收方、加入未选材料或由材料文本扩大权限。

## 7. 需求满足与价值判断标准

- **资料与稿件可持续使用**：同人资料能够复用，多份目标简历可独立维护并重新打开；不同人物不串用，稿件不相互覆盖。
- **用户能够核查并掌握决定权**：材料可检查修正，建议的依据与未知可辨认；未确认的内容不被当作事实，未经授权的修改不进入工作区简历。
- **成果状态可信**：异常和失败明确告知，未保存内容受到保护，不误报保存成功。
- **确认背景可复用且可控**：重新打开及同人工作区可复用已确认背景，不无故重复询问；错误记录能纠正或撤回，材料推测不混入背景。
- **成本收益有证据**：按第 3 节比较同类任务的总成本；满足功能需求不等于已证明省时、省钱或优于普通模型。

以上是需求层面的判断标准，不替代具体功能验收用例或模型效果测试记录。
