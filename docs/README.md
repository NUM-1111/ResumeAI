## 阶段和切片

阶段位于 `docs/阶段/`，第一阶段为 `P1_MVP`。每阶段包括 README、阶段设计、切片开发。设计依次为01需求分析、02产品设计、03交互设计、04技术方案、05开发计划；05负责范围、依赖和验收标准，不承担每日进度。

第二阶段目标明确后创建 `P2_阶段名称`，切片使用P2-01、P2-02，后续类推。第二阶段只描述新增与变更，未变化规则引用MVP设计。小修复直接记录在切片，无需补齐五份设计。未明确范围前不创建空阶段。保留M00—M09编号，不修改代码、测试或数据库迁移名称。

## 职责与维护

| 文档 | 职责与更新时机 |
| --- | --- |
| 根README | 简介、快速启动、导航；入口变化时更新 |
| 开发进度 | 唯一当前状态；推进时更新 |
| 阶段README | 阶段范围、交付结论、接受限制；开始和收尾时更新 |
| 阶段设计/05 | 切片计划；范围或验收标准改变时更新 |
| 切片开发 | 实现、验证、失败和体验证据；执行时记录 |
| 使用指南、工程指南 | 当前行为与操作；实际行为改变时更新 |
| 待办与已知问题 | 问题状态、归属和来源；出现、计划或关闭时更新 |

每片默认使用开发与验证.md，有用户操作再加页面体验.md；复杂排障按需增加专题。既有文件名保留，不补空文件。

验证记录应包含日期、版本（可确认时写提交号）、环境与数据范围、步骤或命令、实际结果、证据位置和限制。区分替身、真实API、浏览器和用户体验，未执行不得写通过。

已交付阶段保留历史基线，允许补充最终结论与更正事实；下一阶段需求不倒写成MVP原承诺。历史正文“进行中”等为当时状态，以阶段README最终结论为准；未执行实验仍为未执行。遗留问题链接原证据，不复制整份排障过程。

当前指南持续更新，历史操作通过阶段记录及Git追溯。现行状态索引已合并到开发进度，不再维护重复状态表。移动文件同步修改链接和脚本引用，执行：

```bash
python3 /root/java/ResumeAI/scripts/check_docs.py
git -C /root/java/ResumeAI diff --check
```

凭据、个人资料、数据库及私有日志不提交。历史核心交接仅作背景，不覆盖当前操作与已确认设计。
