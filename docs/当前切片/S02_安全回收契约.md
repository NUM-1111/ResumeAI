# S02 安全回收与恢复契约

S01用户反馈：除删除缺失外基本交互可接受，收口其已实现范围，不代表全系统验收。S02只增加档案/工作区/材料的影响预览、软删除、回收站、恢复，不永久清理，不做模型或全面视觉改版。

## 数据与规则

V3为三个根表增加recycle_batch，新增recycle_entry保存批次、档案、根类型、根ID、名称、时间及恢复状态。原件、正文、历史修订及历史出处不物理删除。工作区子数据通过根对象生命周期不可访问；回收工作区不回收共享材料。档案回收仅标记仍有效子对象，恢复只清同批次标记，不复活此前独立删除项。恢复工作区/材料要求档案有效；重名对象以原ID独立恢复，不覆盖其他对象。

材料若仍被任何当前来源绑定使用（包括回收中工作区，以保证其恢复关系），禁止回收，列出区名和状态，提示先恢复并更换该区当前简历。历史出处不阻止回收；材料恢复不自动增加任何引用。当前切片无辅助引用和AI任务，无需伪造建议失效处理。

## HTTP

- GET `/profiles/{p}/deletion-preview?kind=PROFILE|WORKSPACE|MATERIAL&id=UUID`：返回名称、影响说明、子对象数量、阻止原因和impactVersion。不返回正文。
- POST `/profiles/{p}/recycle-operations`：kind/id/impactVersion/confirmed=true，CSRF和Idempotency-Key必需。事务锁档案后重算预览；变化409，未确认400，被绑定409。成功返回回收条目。
- GET `/recycle-entries?limit=20&after=UUID`：操作者认证，含已回收档案入口，按批次ID游标分页，仅未恢复条目。
- POST `/profiles/{p}/recycle-entries/{entry}/restore`：confirmed=true，CSRF和幂等；校验归属、父对象和批次，原子恢复。不提供清空/永久删除接口。

impactVersion对档案内根状态、材料名称/版本、工作区属性/当前修订、来源绑定做摘要。任何相关并发变化要求重新预览；事务按档案锁序列化，不跨档案串用。重复请求同键返回首次实际结果，不再次执行。正常列表、详情、保存、初始化和复制均拒绝回收对象。

## 页面和验证

选中档案时可删除档案，工作区操作区可删除工作区，材料操作区可删除材料。先保护未保存文本，再展示独立确认弹窗；取消无写入。顶部回收站分页查看，恢复显式确认。助手验证跨档案、CSRF/匿名、预览过期、绑定阻止、同批次恢复、父对象无效、幂等、事务回滚以及真实浏览器流程；用户只体验新增删除/恢复路径。
