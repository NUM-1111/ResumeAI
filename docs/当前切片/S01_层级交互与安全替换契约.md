# S01 层级交互、重命名与安全替换

本轮经用户批准实现：三级导航、弹窗创建、中间内容/右侧操作、材料重命名、已有当前稿安全替换。保留自动保存和全部历史，不实现删除、参考引用或用户命名版本。

## 接口与事务

- `PATCH /api/v1/profiles/{p}/material-imports/{m}`：`name`（1—200字符）、`expectedVersion`。归属检查后按版本更新展示名称，递增 rowVersion；不改正文、原件、绑定或历史。冲突409，不覆盖。确认接口可同时传 name，与正文检查确认原子完成，避免确认前改名被忽略。
- `POST /api/v1/profiles/{p}/workspaces/{w}/resume/replace`：`sourceId`、`expectedSourceRevision`、`expectedRevision`。仅接受同档案已确认材料；当前稿必须存在；两个版本均匹配才写入。新修订 reason=REPLACE，保留全部旧修订；当前来源绑定改为所选材料，旧修订 source 字段不改。无辅助引用/事实变更。
- 两接口沿用 CSRF、Idempotency-Key、档案事务锁和失败响应。幂等重试不重复修订。无表结构新增，不改已执行的 V2。

## 用户授权

打开材料仅预览/检查。只有点击“改用这份简历”后，弹窗显示工作区、替换前后全文、旧稿保留与来源绑定变化；再明确点击“确认替换”才调用替换接口。预览冻结两个预期版本，确认期间不刷新版本以绕过冲突。取消不写回。进入预览前保存当前稿；未保存/冲突则阻止替换并提供复制。

## 验证

后端：重命名持久化、确认同时改名、跨档案拒绝、旧版本拒绝；替换已确认校验、来源/当前版本冲突、幂等、旧稿保留、绑定更新、并发保存冲突。
浏览器：逐层进入返回、弹窗取消/字段错误/新建选中、中间材料预览不误改当前稿、重命名重开、替换取消与确认、自动保存重开、冲突保稿、窄屏布局。全部使用合成数据；用户体验尚待验收。
