# S01 第二轮交互反馈与下一轮实现依据

> 状态更新：用户随后批准五步实施；三级导航、弹窗、中间内容、材料重命名、重载文案及安全替换现已实现。实际验证见[层级交互整改验证](S01_层级交互整改验证.md)。下文保留反馈发生时的缺陷判断，不代表当前仍全部未实现。材料引用、删除、命名版本仍未实现。

## 验收事实

用户报告登录、当前稿编辑保存重开及离开保护可用；登录错误不区分口令长度可暂不处理。整体交互仍未接受。用户已更正最初判断：当前稿能够编辑，问题在初始化入口隐蔽，而非编辑完全不可用。未把用户快速刷新成功外推成任何关闭场景均不丢内容。

## 明确的交互方向

左侧采用文件管理式层级，不叠放全部层级：档案列表 → 当前档案的工作区列表 → 当前工作区的内容导航；提供返回上一层和上下文路径。前两层选择不需要中间区域额外确认。创建档案/工作区用带文字的“＋新建”入口，弹窗填写并创建，取消不创建；列表不常驻创建表单。工作区显示名称与方向，方向不是独立工作区唯一标识。

进入工作区后左侧区分“当前简历”“档案简历材料”和“参考材料”。后两类不能混同：现有S01 material-imports只实现简历来源材料，没有类型、辅助引用或AI上下文机制；参考材料区暂明确未实现，不能把所有档案共享材料伪装成本区已引用文件。档案材料仍归档案共享，不因导航放在区内而改变归属。

中间显示所选内容：当前简历编辑、待检查材料文本检查、已确认材料预览。右侧显示与所选内容对应的操作，不常驻材料正文。打开材料不等于替换当前简历；必须显式“作为当前简历”。已存在当前稿时不能重用初始化接口偷偷覆盖，需单独替换预览/确认/版本校验契约。没有选材料时才展示引导。

## 缺陷及范围

1. 材料名输入可编辑但确认接口只收text/expectedVersion，修改名称被忽略：确认为缺陷。下一轮应让名称保存有真实服务端行为，或未实现前只读并说明，不能继续提供无效输入。重命名修改展示元数据，不改原件/正文和历史出处；须归属、版本、幂等校验。
2. 已确认材料正文不可原地修改是S01已明确边界，正文更新需新材料修订，不能为UI便利覆盖已确认文本。当前稿编辑是独立文本，不回写原材料。
3. 已有稿件不能改用简历2：当前S01明确排除替换流程，确为尚未实现功能，不是用户找错按钮。下一轮须明确纳入安全替换子切片后实现，不借初始化绕过限制。
4. “重新打开服务端当前稿”改为“重新载入已保存内容”，说明用于读取服务器内容，页面有未保存修改时先保护；不是恢复旧版本。
5. 删除/回收站仍未实现，不永久删除或清测试库。参考材料引用、材料正文修订、简历替换和用户版本管理分别列为后续业务子切片，不能一并塞进视觉整改。

## 技术修订和用户版本

07第4.2节已确认“变化保存保留修订，但不把每次按键作为用户可见版本”。当前900ms停顿保存实际追加修订，页面展示v13误导用户把并发控制号当发布版本。下一轮隐藏主界面技术修订号，保留已保存/保存中/失败/冲突；技术值继续参与expectedRevision校验。自动保存不取消，既有记录不删除。

用户提出“主动确认大版本”作为后续需求方向，尚未实现。建议命名快照/里程碑与自动保存并存；按用户动作保存快照，历史恢复生成新当前修订；自动保存不产生用户里程碑。快照名称、列表、恢复及保留策略需在该子切片收口，不预先宣称已有完整版本管理。

## 下一轮交付顺序

先做层级导航、创建弹窗、中间内容预览检查、右侧上下文操作、重载文案及修订号展示纠正。再完成材料重命名的最小接口与测试。安全替换在单独契约明确后实现；参考材料、删除与命名快照不随UI顺带生成。助手验证主路径、取消弹窗、返回导航、不误替换、未保存保护后再请用户体验；不要求F12和UUID。

本文件为反馈和实现依据，不代表上述下一轮功能已经实现。本轮仅记录和核对，没有改业务代码或运行业务测试。
