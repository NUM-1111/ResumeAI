## 1. 执行规则与准备

## 2. 登录与口令 P01—P03

### P01 设置长度边界（操作人执行，不泄露密码）

- 前置：先Ctrl+C停止应用；记住你原来的口令。此用例会主动修改自己的口令，最后设回你想保留的值。
- 步骤：set-password先输入5字符两遍，检查报错和非零退出（紧接 `echo $?`）；用6字符两遍设置成功；再用32字符两遍成功；33字符两遍失败；两遍不一致失败；最后设置最终使用口令并重启。
- 预期：长度允许6和32，拒绝5和33；失败不覆盖此前散列；终端不回显明文。旧密码只在成功更换并重启后失效。
- 核对：自动边界测试为 `python3 /root/java/ResumeAI/scripts/test_passwords.py`；人工无须查看credentials.json。记录成功/失败和退出码，不记录密码本身。

### P02 登录/退出

1. 隐私窗口打开首页，应看到登录表单而非工作台。
2. 错误口令提交一次，应仍未登录（默认表单可能显示英文Bad credentials）。
3. 正确口令登录，应看到“AgentCV · 文本简历工作台”。
4. 最后在无未保存内容时点“退出登录”，应回登录页；访问 `/api/v1/profiles` 应401，不能返回档案列表。

核对：登录为POST /login、成功跳转首页；API未登录401；这不等于不同人拥有不同账号，当前只有一个操作者。

### P03 登录限流（建议自动执行）

进程内对POST /login计数，所有提交计入，一分钟最多10次，第11次429、Retry-After=60；重启清空。不要在主验收前连错十次堵住自己。当前LoginRateTest验证窗口算法，真实HTTP限流尚须单列执行结果，不能用算法测试冒充浏览器攻击测试。

## 3. 正常主流程 U01—U07

### U01 创建档案与工作区

1. “新档案姓名”填甲→“创建档案”；再填“工作区名称”A、“岗位方向”Java后端→“创建独立工作区”。
2. 核对标题为甲/A，显示方向，中央“待初始化”，没有可编辑“当前简历”。
3. Network：POST /api/v1/profiles与POST /profiles/{甲ID}/workspaces为201，记下甲ID和A ID；不要抄错为乙ID。
4. 空名称、空方向分别尝试，应明确报错且不创建成功。服务端400；刷新后列表不得出现对应空对象。

### U02 粘贴并保存待检查材料

1. 右侧“材料名称”填本批次名称，“材料检查文本”粘贴A→“保存为待检查材料”。
2. 应显示“待检查”，出现“确认检查后的文本”；中央仍待初始化。
3. 初始化下拉不包含未确认材料。保存材料本身不能改当前稿。
4. Network：POST material-imports为201，`checkState=UNCHECKED`、`rowVersion=1`、`extractedText`逐字等于A。记录材料ID。

### U03 检查修正与确认

1. 将职责行改为B，点“确认检查后的文本”。
2. 应提示“文本已检查确认可用，不代表确认经历真实”；材料“已确认”、检查框只读；中央仍待初始化。
3. Network：POST material-imports/{ID}/confirm为200；`checkState=CONFIRMED`、`rowVersion=2`、`confirmedText`为B；原`extractedText`仍为A。
4. “已确认”只代表提取文本检查，不代表系统确认职责、成果或数字真实；本切片没有事实同步接口。

### U04 初始化独立当前稿

1. 起始稿下拉选择本材料→“以所选材料建立当前稿”。
2. 中央应显示B，状态“已保存 · 服务端修订 v1”。
3. Network：POST resume/initialize为200；sourceId为本材料，expectedSourceRevision=2；响应initialized=true/revision=1/text=B。
4. 初始化后界面不再提供覆盖式初始化。接口重复初始化不同请求应409，不能覆盖已有稿（通过自动测试/接口附录核对，不修改真实对象）。

### U05 编辑、自动保存与重开

1. 中央B末尾追加技术栈成为C，停止输入至少2秒；允许网络慢时继续等待，不以固定2秒判断必定成功。
2. 过程应出现未保存/保存中，最终已保存；最终响应到达前不得提前认定成功。
3. Network：PUT resume含text=C、expectedRevision=1、clientEditSequence；响应revision=2，回显相同序号和C。
4. 点“重新打开服务端当前稿”，C/v2不变；刷新页面，重新选甲/A，仍为C/v2。刷新后未自动选区是现有行为，不算数据丢失。
5. 单击“立即保存 / 重试”且未改字，不应新增修订。若再次编辑且自动保存多次，版本可能超过2，此时以实际成功PUT次数核对，不套用旧数字。

### U06 同人多区、复制独立

1. 同档案创建B，方向仍Java后端；来源区选择A→“复制为独立当前稿”。
2. B文本为A当时的C，B自己的初始修订v1；没有覆盖A。
3. B改为“副本独立编辑”，等待保存成功；返回A，仍为C。
4. 再建空区C，不初始化；C不应因创建或切换自动获得A/B稿件。
5. 复制来源选空区C时，应提示来源区尚无当前稿，不生成空稿。辅助资料、JD、任务不会自动复制；本切片无相关功能。

### U07 双人物隔离

1. 创建乙及乙工作区；材料列表和来源工作区列表不得出现甲材料及A/B。
2. 返回甲，稿件仍完整；乙新建不会改甲。
3. 前端不可见仅验证界面隔离；服务端ID篡改保护须运行后端测试或附录中的只读GET核对，不据列表隐藏宣称授权已全测。

## 4. 文本文件与异常 I01—I04

### I01 UTF-8 txt

点击“新建文本导入”，选择本机保存为UTF-8的`.txt`（可带BOM），内容用合成稿。确认预览中文逐字正确，保存待检查→修正→确认。不要默认上传就初始化；已有稿时不会出现覆盖按钮，要到新空区选确认材料。文件读取后修改检查文本再保存会改走粘贴文本接口，属于当前实现。

### I02 重复输入

再次导入同名或同字节文本，首次请求409 DUPLICATE，出现“确定保留两份吗”确认框。点取消：旧材料、当前稿不变，不应出现第二份；可保留错误提示。再次操作点确定：新材料不同ID、待检查；原已确认材料不覆盖。比较更新本切片未实现，不把“保留两份”当覆盖更新。

### I03 非UTF-8、不支持类型、容量

- 无效UTF-8 .txt：读取阶段报错，不能出现乱码成功材料。
- .doc/.docx/.pdf：当前仅txt，拒绝并提示；不能据此说首轮最终格式需求被取消。
- 大于256 KiB：拒绝；空白文本或NUL等控制字符拒绝；失败不改变当前稿。
- 文件选择器可能过滤非txt，可选“所有文件”测试；无法选入则记录客户端过滤，不等于服务端拒绝已验证。编码及服务端限制已有后端测试，人工另记结果。

### I04 跨人来源/未确认请求

使用WorkspaceIntegrationTest中confirmationIsolationAndIndependentCopy验证跨人来源和未确认初始化。普通用户不需要手工造POST；如果只完成页面U02/U07，报告应写“页面检查通过，服务端断言引用自动测试”。

## 5. 故障与冲突 F01—F05

### F01 两标签版本冲突

1. A已保存后，在两个标签分别选择甲/A，确保起始revision相同，记为n。
2. 标签1改D，等待保存为n+1。
3. 标签2改E，自动保存应409 VERSION_CONFLICT；状态“版本冲突 · 未保存 · 服务端修订 vn”（显示该页基础版本，不是实时服务器版本）。E仍在，不被D替换。
4. 新开第三页读甲/A，实际为D/n+1，证明E没有覆盖。冲突页不要刷新后宣称E被保存。
5. 冲突页复制E到本地，再点重新打开；确认明确放弃后应读D。版本冲突按钮不会自动解决差异，也没有合并功能。

### F02 保存失败、切换保护、重试

1. A已保存且无其他编辑。DevTools Network选Offline（浏览器实现可能仍允许localhost；若请求没有失败，用F03的Playwright拦截，记录该人工用例BLOCKED，不能假报通过）。
2. 中央改为“断网未保存稿”；请求失败后应显示“保存失败 · 未保存”，页面文字保留。离线可能先失败于GET csrf，或失败于PUT；都不能报成功。
3. 点其他工作区或重开，若出现未保存提示点取消；应留原页并保留稿，不静默切走。
4. Network恢复Online，显式点“立即保存 / 重试”；成功后刷新重开确认正文相同。复制文本不能改变失败状态。
5. 本用例不停止数据库，不模拟磁盘满，避免影响其他操作。

### F03 保存响应期间继续编辑 / 丢响应

前端自动测试覆盖确定性时序：发送第一稿后未返回时编辑第二稿，第一稿响应不能把第二稿标已保存；丢响应重试同key，再保存第二稿。命令见第7节。浏览器Slow网络可辅助观察但不是稳定判据；没有确切请求/响应证据时不填写PASS。实际网络中断保稿由browser_s01.py验证。

### F04 剪贴板复制与兜底

1. 当前稿中输入唯一短句，点“复制页面文本”，粘贴到本机临时编辑器，逐字比较；不把提示“已复制”单独作为证据。
2. 浏览器网站权限中阻止剪贴板（不同浏览器可能无此开关），再点复制；若失败应出现只读“复制兜底文本”，点入全选，手动复制对照正文。
3. 复制前后revision、保存状态不得因复制而变化。没有成功强制拒绝权限时，兜底分支标NOT RUN；不允许声称已有正常复制测试证明失败兜底。

### F05 退出/重启/关闭页面

有未保存内容退出登录须按同样保存/离开保护；正常退出后API401。重启应用会失效服务端内存会话，重新登录并选区后只能恢复已保存稿。beforeunload警告不保证所有浏览器显示自定义文案，不承诺关闭后恢复未保存内容。测试关闭前先复制未保存稿，不使用真实资料。
