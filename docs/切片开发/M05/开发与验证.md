## 本片实现

- V7 追加 conversation_state、conversation_draft 及请求 visible 标识，不改历史迁移。
- 每工作区一段对话和一份草稿；草稿单独版本和上下文代次校验。草稿失败保留文字并允许发送，切区尝试保存，失败可复制/明确放弃；刷新只保证恢复已保存部分。
- 发送带 expected_conversation_version/expected_context_epoch。另一页新增消息或重置后，旧版本发送拒绝；页面同步显示新状态，需主动核对，不自动提交。
- 请求上下文包含分隔点后的近期完整成功问答，按当前 192 KiB 本地预算选择，不截断半条，不自动摘要。必需资料放不下仍拒绝，不静默删减。
- 停止参考时提示模型仅以当前资料白名单为有效依据；旧聊天可能仍含材料摘录，不能承诺遗忘。需要排除则创建分隔点，不沿用供应商会话 ID（当前本就无服务端会话关联）。
- AI 顶部菜单分别提供“不携带此前聊天，继续对话”及“清空记录并开始新对话”。在途/未保存回答阻塞这两项。分隔保留旧消息及草稿；清空删除消息正文，清除请求正文/回答/输入快照并隐藏旧请求，保留无正文幂等墓碑，防旧操作自动重新外发。
- 草稿提交成功只清对应发送文字；回答返回不清新写草稿。草稿冲突不静默覆盖，核对别处文字后可主动选择以本页为准。
- 消息初始读取 50，使用 offset/limit 逐批加载更早；单次上限 1000，不作为总历史数量上限。并发新增时分页不承诺一致快照，客户端按请求 ID 去重。

## 目标接口

工作区路径 `/api/v1/profiles/{p}/workspaces/{w}`：

| 接口 | 约定 |
| --- | --- |
| GET `/conversation-state` | version/epoch/boundary_at |
| GET/PUT `/draft` | text/version；保存带 expected_version/expected_epoch，幂等和 CSRF |
| POST `/context-boundaries` | 对话版本/代次条件，保留旧可见消息 |
| POST `/conversation/clear` | 对话版本/代次条件，清空消息与草稿，不改简历材料 |
| POST `/conversation` | 新增对话版本/代次条件，受理时固定历史和资料 |

## 尚需补齐与限制

本轮补充验证：最终构建与 31 项后端测试通过。新增容量用例确认超长旧问答整轮排除，近期完整问答仍进入请求；清空同时删除草稿幂等结果中的文字，避免留下旧草稿副本。回答保存与上下文操作采用相同工作区锁序，防止结果落库和清空交错。

M05 浏览器最终复测通过，包括两标签页清空后旧页输入保留但暂停写回、模拟延迟发送响应期间输入下一条草稿不被清空、该草稿刷新后恢复。所有发送模拟均在浏览器本地拦截，不外发模型，不增加实际调用费用。参考资料弹窗与独立滚动回归通过。
