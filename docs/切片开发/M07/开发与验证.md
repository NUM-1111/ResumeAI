# M07 开发与验证

## 确认入口归属与编辑弹窗修正

用户进一步说明需要“点击纠正即弹窗编辑”，而不是仅最后一步弹窗，并指出中间与 AI 栏重复确认。上轮对需求理解不完整：编辑仍在条目下，右侧轮询未区分提议来源。

本轮按用户认可方案：列表“纠正”立即打开原生编辑 dialog，输入和提交在弹窗内；提交成功后进入确切前后文本确认弹窗。列表“撤回”直接打开确认弹窗。关闭/取消不执行变更，保存失败保留相同提议重试。右侧轮询只接受 source_request_id 非空的对话来源提议，列表提议不显示右侧入口，也不能经右侧文字确认。后台契约和版本保护不变，不增加迁移、不调用模型。

浏览器验证实际 HTTP 列表操作，明确断言编辑弹窗可见且输入获焦、前后对照、失败重试、撤回取消与确认、草稿保留；在待确认时等待实际 background-changes 轮询返回，断言列表来源不会在 AI 栏出现确认按钮。对话来源另用显式 fixture 验证仍可打开确认弹窗，关闭后保留待确认入口；这部分不冒充真实模型效果。首次烟测列表按钮等待超时，重跑通过，补充标题加载和显式刷新等待后继续复测。

## 最终确认弹窗与用户体验结论

用户确认除最终确认不醒目外，M07 无其他问题、功能稳定。按反馈将纠正/撤回的确切内容确认改为原生 dialog 模态弹窗：列表提交后立即打开，原文与拟修改内容对照，默认聚焦取消，Escape 取消，保存中禁止关闭/重复确认，失败在弹窗内说明并保留相同提议供重试。关闭后恢复可用焦点。对话轮询得到提议时显示“核对并确认背景变更”入口，由用户打开相同弹窗，避免列表和聊天同时弹出重复对话框。

用户要求单独解释 UNKNOWN 数据过程，已形成 [调用结果不明的数据流程](调用结果不明的数据流程.md)，覆盖受理、执行快照、HTTP 总期限、状态落库、轮询与固定文案、风险确认、停止等待、清空及保存失败的区别，作为后续学习入口。

用户对已有功能的体验认可已记录；本次弹窗变化仍以实际浏览器验证和后续体验为准，未执行的真实模型与恢复实验不补记成功。

本次验证通过：前端类型检查/构建、45 项后端测试、M07 实际 HTTP/Chromium。浏览器断言确认弹窗可见、初始焦点在取消、模拟保存 503 后弹窗保留并显示错误、解除故障后重试真实保存、Escape 取消撤回以及草稿保持。文档链接与空白检查通过；无真实模型调用。

## 页面反馈：入口位置与自行纠正

用户建议将“查看个人背景”放到左侧导航，并反馈未找到纠正按钮。本次将主入口从 AI 顶部移至左导航，与个人材料相邻；窄屏通过“导航”展开后进入，中间正文展示背景。保留参考资料弹窗中的上下文查看入口。列表增加明确操作说明，每条已保存记录提供“纠正/撤回”，用户可直接编辑，不依赖 AI、不调用模型。

核查时 8081 返回的静态资源为此前 M07 包，包含列表纠正代码，不能将用户现场直接认定为旧服务或未重启；浏览器缓存/实际视图未取得现场证据。新增浏览器断言验证左导航入口、AI 顶部无重复主按钮、实际列表纠正可见，继续执行真实 HTTP 纠正及撤回路径。

状态：进行中。M06 用户确认暂无其他问题并授权推进；M07 基础实现与首轮技术验证通过，真实模型冲突走读、用户体验及部分组合边界未全部验证，不标完成。

## 依据与实现

依据阶段设计 03 第 5—6 节、05 第 10 节。V9 新增 background_change，绑定人物、工作区、目标背景、目标版本、原文、拟修改内容、操作类型、上下文代次及可选来源请求。复合外键防跨人物，状态 PENDING/APPLIED/EXPIRED。正式 m00_app 启动时增量迁移，自动测试使用 m00_test，不修改历史迁移。

- 背景列表原位纠正：输入→提交拟修改内容→原文/新文对照→明确确认；撤回展示确切原文、后续不再有效和界面无法直接恢复的说明。取消不改变有效记录，失败保留输入/提议，重试仅数据库操作，不调模型。
- 生效操作按工作区→人物锁序执行，目标版本、原文、代次及待确认状态都需一致。纠正递增版本，撤回改变 active 并递增版本。旧确认重放只返回原操作已执行，不重放变更，不恢复已撤回状态；其他页过期操作拒绝。已有有效待确认提议时列表不会静默替换。
- 对话模型协议新增 background_action，携带现有背景 ID/version/old_text/kind/new_text；后台检查受理时背景版本清单及当前真实记录，模型只能形成提议，不能直接写入。页面统一展示原文/拟修改内容，按钮确认，也支持当前提议对应的“确认纠正”“确认撤回”“确认删除”或“确认”。目标不唯一时模型应先澄清。
- 模型输出无效目标、旧版本不执行。新一次普通对话受理使旧待确认提议过期，上下文重置后旧代次也不能确认，避免旧意图继续写入。
- 全部有效背景随请求固定，basis_json 保存背景 ID→版本，回答期间允许修改背景。当前清单变化时旧请求/回答显示“基于变更前的背景、简历或材料”，不重答、不换快照。
- 后续模型输入包含最新有效背景，以及已生效纠正/撤回说明，明确旧聊天不得把失效说法当当前事实或再次恢复成新增候选。背景变更不改简历、材料或旧聊天，不承诺供应商遗忘。
- 四种冲突处理写入协议：不同事件补范围再另行确认新增；原记录不准生成纠正提议；仅讨论措辞不写入；暂缓保留分歧且不反复追问，不阻断无关交流。这是模型行为约束，不是保证发现所有语义冲突的确定算法。

## 接口

统一前缀 `/api/v1/profiles/{p}`，写入带 Idempotency-Key，保留登录/CSRF/归属检查：

| 接口 | 作用 |
| --- | --- |
| POST `/backgrounds/{b}/changes` | workspace_id、expected_version、old_text、new_text、kind（CORRECT/WITHDRAW），创建确切提议 |
| GET `/workspaces/{w}/background-changes` | 当前有效待确认提议，空对象表示无可操作提议 |
| POST `/background-changes/{c}/confirm` | 带提议对应的全部版本/正文条件，应用确切变更 |
| POST `/background-changes/{c}/dismiss` | workspace_id，取消待确认变更 |

## 已执行证据

首轮 TypeScript/Vite 和 45 项后端测试通过。M07 五项数据库/模型替身测试：纠正与撤回版本、旧重试不恢复、不同页面竞争、跨人物拒绝、取消不写入、延迟回答中修改背景不换快照且依据变化可见、后续实际输入包含最新背景和变更说明、对话提议必须独立确认、写库故障回滚后原键重试且模型调用计数不增。

`smoke --slice m07` 真实 JAR/HTTP/Chromium 通过：在 m00_test 写入明确标记的合成背景种子，然后页面纠正、对照确认、撤回取消、确认撤回、刷新有效列表、聊天草稿保留。管理接口无 fixture，使用实际数据库；合成种子不代表真实模型提炼。未读取个人正文或密钥，未发起真实模型请求。

## 限制与未完成验证

- 真实模型对话定位及四种冲突走读待验证；不能以提示词或替身证明真实模型始终正确。无匹配提议时不执行删除；后台不会凭模糊指代选背景。
- 变更说明目前完整携带，长期大量变更可能占用容量，达到预算时拒绝受理而非静默删减；保留/清理策略在 M08 校准。
- 旧请求（M07 前）缺背景版本清单，无法追溯当时未保存的背景依据，不伪造历史快照。
- 已确认背景与变更记录独立于聊天；界面放弃编辑不代表撤销已提交的后台操作，返回时从真实状态查询。所有进程重启、故障组合和跨页时序尚未穷尽。

## 技术认识

纠正/撤回不是让模型生成一句“已删除”。先固定目标和前后文本，再让用户确认，最后用版本条件执行数据库状态更新；这样旧页面和重复请求不能恢复失效内容。请求保存背景版本清单，使“回答生成了”与“依据是否仍有效”可以分别判断。用户无需先读代码，后续可从 BackgroundChangeService.prepare/confirm 和 ConversationService.buildInput/basisChanged 跟踪这两条数据流程。
