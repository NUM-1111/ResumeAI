# M04 初步页面体验

真实 DeepSeek 基础调用已验证，M04 仍在开发验证中；本指南用于初步反馈，不表示全部故障/恢复机制已验收。保持使用合成资料，不上传个人真实经历测试。

`.env` 已配置后，在 Ubuntu WSL 使用已有启动入口。应用正在运行且模型已可用时无需重启；改配置或代码后保存简历，在原终端 Ctrl+C，再执行：

```bash
python3 /root/java/ResumeAI/scripts/skeleton.py run
```

打开 `http://127.0.0.1:8081/`，沿用 operator 和新工程口令：

1. 选择一个只有合成简历的工作区，右侧确认模型服务为 DeepSeek / deepseek-flash；参考材料默认只包含此前你明确选用的材料，不会使用整个人物材料库。
2. 保持“参考工作区简历”开启，输入：“请用两句话指出这份合成简历的职责描述需要澄清什么，不要扩大职责或编造数字。”点击发送一次。
3. 应显示受理/回答状态，结束后看到 AI 公开回答；简历不应被自动修改。刷新页面，应能回看已保存回答，刷新不应再次调用模型。
4. 可取消“参考工作区简历”，询问一个不依赖简历的一般问题；发送会产生新的实际模型费用。没有必要为了验收反复发送。
5. 有选定材料时核对名称和限制，调整范围后点击“刷新发送范围”，核对后主动发送；版本变化导致拒绝时输入应保留，不自动发。

Enter 发送，Shift+Enter 换行，中文输入法选字不应误发。正在回答时不接受第二条，但可编辑文字。

当前只实现单次资料问答：旧聊天虽可回看，暂不随新问题发送；持续上下文及草稿持久化在 M05。此时切换工作区可能丢失尚未发送的聊天输入，请先手动复制，不将它当成已保存草稿。不要用未实现能力判断模型是否记住历史。

若提示调用结果不明，不要反复重试；先反馈状态。若只是回答记录未保存，使用“重试保存回答”，不要重新发送同一问题。密钥不截图、不发聊天；只反馈入口、状态、结果显示是否符合预期。
