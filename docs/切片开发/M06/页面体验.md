# M06 页面体验

基础实现已通过替身测试，待真实模型与用户体验确认。先保存现有编辑，Ctrl+C 停止旧应用，再启动（无需重设口令或密钥）：

```bash
python3 /root/java/ResumeAI/scripts/skeleton.py run
```

1. 使用新建合成人物与工作区，取消参考工作区简历也可测试。在聊天中发送：“以下为合成测试经历：项目 A 中开发订单接口，部署只是协助，不是独立负责。请整理成两项待确认个人背景，不编造结果或数字。”这一步会调用真实模型并产生费用。
2. 等待回答，检查编号候选和用途说明，尤其“协助”未扩大为“负责”。此时仍未保存，背景列表应为空。
3. 在同一输入框回复“仅保留第一项作为背景”或“确认仅保留第一项”（编号按实际候选选择），点击发送，直接保存指定项，不调用模型。全部保存可回复“确认”“确认保存”或“确认以上全部并保存”。只有实际保存成功才显示成功反馈。带修正、否定、假设或新增内容的回复不会被当作这类确认。
4. 点击“查看个人背景”，中间显示实际条目，右侧仍可输入；选择“返回工作区简历”，消息和草稿保持。
5. 同人物新建另一工作区，背景数量相同，主动发送时全部有效背景供模型使用；另一人物不带入这些背景。查看、切区不调用 AI。
6. 如候选职责不准，先在对话中纠正，等最终确切内容重新展示后再明确确认。不要对不准确内容确认。含糊、假设、拒绝或暂缓不会直接保存。

无需重复付费调用来制造故障。背景保存失败时保留原确认，可点“重试保存背景”；继续普通交流仍可，但新候选或对话变化可能要求重新核对。当前尚无已确认背景纠正/撤回入口，这两项由 M07 补齐。

## 本轮四项反馈复测

补充：现在直接回复系统提示的“确认保存全部”即可保存全部候选，也可点击“保存全部候选”。保存成功显示实际条目，可进入个人背景查看；无需再次让 AI 提炼。旧版应用必须保存后 Ctrl+C，再 run 并刷新浏览器，新包才会生效。

- 候选只显示一次编号清单和简短用途，不再重复模型与系统两套确认说明。旧消息正文不重写，新回答采用新呈现。
- 等待中显示“停止等待”。确认提示后可主动发送新问题；本地会尝试中断 HTTP 等待，供应商可能仍执行并收费，迟到结果不再写入。
- 从 HTTP 开始到完整响应体设 60 秒总等待期限，超时不自动重新调用。此前排队时间另计，不承诺供应商在 60 秒内一定成功。
- 出现“调用结果不明”可保留消息并确认风险继续；也可清空记录。清空提示包含旧调用可能收费的说明，清空后不要求找回已删除消息去确认风险，直接允许新问题。
- 如果旧版本已经发生清空后卡死，更新并重启后即可解除隐藏未知请求的门禁，无需手工改数据库或删除人物。
