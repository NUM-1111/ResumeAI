# AgentCV 使用指南

目标是整理真实经历、核对职责和措辞，帮助你完成目标岗位简历。AI 提建议，是否采用由你决定；系统不会自动改写简历。

## 打开工作台

在 Ubuntu WSL 终端执行：

```bash
python3 /root/java/ResumeAI/scripts/skeleton.py run
```

等待启动成功，打开 http://127.0.0.1:8081/ ，账号 operator，使用已设置口令。日常无需重新配置密钥或口令。停止前等待保存完成，再在运行终端 Ctrl+C。改代码后需构建新包、重启并刷新浏览器。

## 建立一份目标简历

1. 创建或选择个人档案，可用化名；每个人物资料相互隔离。
2. 创建工作区，按目标岗位命名，例如“Java 后端—目标版”。工作区名称和方向用于辨识，不自动生成内容。
3. 上传 TXT、DOCX、带文本层的 PDF，或粘贴已有简历。核对提取文字后点击建立；扫描图片不能保证提取，不支持 OCR。
4. 简历正文自动保存，等待“已保存”再离开。来源原件在“来源信息”查看，不随正文修改，也不会自动成为个人材料。
5. 另一个岗位可新建工作区，复制同人物其他工作区简历；之后分别编辑，互不影响。

## 添加参考资料

“个人材料”独立保存项目说明、补充经历等，可不选工作区，也可供同人物多个工作区参考。添加不等于确认材料每一句属实。

右侧“参考资料”核对是否参考当前简历、选定材料和全部有效个人背景。选择/取消资料不调用模型，主动发送才外发。材料编辑需手动保存，发送使用已保存版本；停止参考不删除旧聊天摘录。

## 用少量问题完善简历

先明确一个目标岗位，按实际需要选几个问题，不必每次完整重问：

- “请找出这份简历中职责不清的三处，先追问，不要补造经历或数字。”
- “这是目标岗位要求，请按实际经历指出匹配点和缺口，不把参与写成独立负责。”
- “根据刚才确认的信息，给这一段两种简洁写法，保持事实不变。”
- “面试官最可能追问这段项目经历的哪五个问题？分别需要我准备什么证据？”

核对回答后，手动把认可内容改到中间简历正文。刷新确认已保存，再复制文字到现有文档工具排版、检查联系方式/时间/事实并导出投递。本应用目前没有正式排版导出功能。

发送会调用 DeepSeek 官方 deepseek-flash（当前对应版本以官方说明为准），可能产生费用。历史仅按容量携带近期完整交流，不保证模型记得所有消息，也不自动摘要。

## 保存、纠正和撤回个人背景

聊天可以整理候选，候选尚不算有效背景。核对准确后回复“确认保存全部”、指定只保存哪项，或使用“保存全部候选”。以真实保存成功反馈为准，不能只信 AI 说“记住了”。

左侧“查看个人背景”显示实际记录，同人物所有工作区共用；不同人物不混用。点“纠正”在弹窗修改，再核对前后内容并确认；“撤回”确认后不再有效，不删除简历、材料或旧聊天。列表操作不调用模型。

可在对话中请求修改，模型先定位或澄清，再由“核对并确认背景变更”打开确切提议。指向不明不要确认。列表提议刷新后可用“继续处理待确认背景变更”找回并确认或取消，不必清空聊天。

## 草稿和上下文

右侧“向 AI 提问”输入框每个工作区保存一份独立草稿。等待“草稿已保存”后，重开恢复，不自动发送。这不包括未保存的简历、材料编辑或背景编辑框。

对话菜单两项有不同作用：

- **不携带此前聊天，继续对话**：旧消息可回看，后续不发送分隔前聊天；简历、材料、背景和草稿不变。
- **清空记录并开始新对话**：清空本区聊天及草稿，界面不能恢复；简历、材料和有效背景不变，也不能撤回已外发内容。

## 遇到失败

| 提示 | 怎么处理 |
| --- | --- |
| 输入或资料未保存 | 保留页面文字，按对应保存入口重试；冲突先核对最新内容 |
| 回答未保存 | 先复制或重试保存回答；不重新调用模型，重启可能丢失内存暂存 |
| 调用结果不明 | 不代表未执行或没收费；查询/确认风险后再主动发送，不反复点击 |
| 等待过久 | 可“停止等待”，供应商可能仍执行并收费，迟到结果不会再写入 |
| 暂时无法获取状态 | 查询失败不等于模型失败，恢复查询原请求 |
| 登录过期 | 原页重新登录，核对后主动操作，不自动重放写入 |
| 已有待确认背景变更 | 到背景列表恢复处理并确认或取消 |

当前为本机单操作者、单执行器应用，不作为公网多人服务。完整 HTTP 等待期限默认180秒（可配置），排队另计，可主动停止等待；期限不保证供应商成功返回。备份迁机需同时考虑数据库、原件和本机配置，现有脚本不是全新机器的一键安装器。不要公开 API key、口令、日志或个人资料截图。
