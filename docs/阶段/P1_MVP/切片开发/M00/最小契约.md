# M00 最小契约

M00 不提供人物、简历、材料或背景业务。按阶段设计，业务随 M01 起逐片实现，不预先建空服务和完整表。

## 工程与模块

- 前端为 Vue/TypeScript/Vite，开发代理仅将 `/api` 转至回环 8081，打包后同源提供静态资源。
- 后端保留启动类、安全配置和 `SystemStatusController`；后续按档案工作区、简历、材料、背景、对话请求划分业务包，模型与存储通过适配边界访问。无业务时不生成空实现。
- 默认配置可运行无库骨架；正式 M00 入口由 `scripts/skeleton.py` 强制选择 `m00` profile，连接专属容器、55434 端口、`agentcv_m00` 数据库及 `m00_app` schema。应用账号 `agentcv_m00_app` 非超级用户，不能创建数据库/角色。
- Flyway 只读 `classpath:db/m00`，V1 仅创建合成工程标记；不是简历业务表。不加载 legacy 迁移。后续已执行迁移只追加。
- 旧 55433、旧文件目录和旧凭据不作为输入；新凭据只在 `.local/m00/postgres.env`，目录 700、文件 600，不提交。

## HTTP 与后续业务约定

`GET /api/v1/system/status` 返回 200，JSON 为 `{"application":"AgentCV","stage":"skeleton"}`。这是进程连通状态，不冒充数据库实时就绪检查；数据库健康通过集成测试/Flyway 实际检查。

静态页和该接口无个人数据，允许匿名。其他路由拒绝，匿名 GET 为 401，无 CSRF 的写请求为 403。完整登录、中文业务错误结构及登录限流随 M01 交付，当前没有通用写业务入口。

后续错误 DTO 固定遵循 04：`code/message/retryable/request_id`，不含正文或凭据；更新使用预期版本，业务写入使用幂等键。幂等记录与业务结果同事务，同键异载荷冲突，提交结果未知先查原操作。M01 首先实现和测试这些规则，不在 M00 伪造可调用的业务接口。

## 验证分层与范围

| 层次 | 当前入口/用例 | 证明范围 |
| --- | --- | --- |
| 类型与构建 | `skeleton.py verify` 的 npm build | TypeScript 和资源编译 |
| HTTP/安全 | `SkeletonIntegrationTest` | 状态接口、未开放业务路由拒绝、CSRF |
| 真实数据库 | `M00DatabaseIntegrationTest` | 数据库/schema/账号、非超级权限、中文标记、Flyway 可重复 |
| 打包与浏览器 | `skeleton.py smoke` | 真实 JAR、静态页、JS 请求、1440/390 宽度、无运行时异常 |

数据库集成测试在未提供 M00 凭据时会跳过，因此单独执行 Maven 不代表 M00 通过；权威入口为 `skeleton.py verify`，报告必须是 3 项执行、0 跳过。后续业务用合成固定数据、独立目录，受影响前片回归，模型替身和真实调用分别记录。

模型服务商尚未确定。本片可继续技术基线，不阻塞于缺少模型密钥；M04 真实调用验收前核验模型、费用、容量、数据条款和实际幂等/查询能力。这里不沿用历史供应商决定，不声明已接入。
