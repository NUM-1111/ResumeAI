# 最终体验与交接

当前最终切片进行中，基础功能已经可用，尚未将完整 MVP 标完成。请从 [使用指南](../../../../使用指南.md) 开始，不需要逐片重新测试。

## 一条实际任务

1. 保存现有编辑，Ctrl+C 停止旧应用，再 `python3 /root/java/ResumeAI/scripts/skeleton.py run`，刷新进入。
2. 选一个目标岗位，建立工作区简历，核对上传文字与来源；另建一个工作区复制一次，确认互不影响。
3. 按需要添加补充材料并明确选择参考。主动问 AI 哪些职责不清、哪些表述缺事实支撑。真实资料外发需自己判断，模型数据处理条款尚有核验限制；可以先用合成资料串联。
4. 对准确背景明确确认并查看实际列表，切到同人物另一工作区继续。必要时纠正/撤回一条合成背景，确认生效；不为制造故障重复调用。
5. 手动把认可表达写入工作区简历，等待已保存并重开确认；让 AI 精选3—5个面试追问，记录自己还需补充的事实。
6. 把最终文字复制到现有文档工具排版、检查并导出。此项目不提供正式排版导出，也不把输出建议自动当作事实。

草稿、资料切换、背景弹窗和待确认恢复应保留；列表操作本身不调用模型。异常流程已按前片自动化证据暂时通过，无需破坏运行环境。

测试完成后再次查询，前后总余额差作为该时间段账户扣费近似值（包含赠送余额扣减），不当作精确单请求账单。同账户其他客户端消费、结算延迟及返回金额精度都会影响结果；差额0.00不能记为免费，应记“余额显示精度内未见变化”。可再按本次时间/工作区限定成功请求的供应商用量，结合当时官方价格估算；UNKNOWN未返回用量的潜在消费不凭空补算，也不使用全库混合测试汇总作为实际费用。
