# AgentCV 产品设计（审阅稿）

> 承接需求分析，说明功能、优先级、MVP 边界和核心链路。最新确认：MVP 包含 AI 对话及最小用户背景整理；参考材料不要求逐份真实性认证或强制人工检查确认。最新决定覆盖历史基线中的对应安排，其余取舍沿用基线。本文不规定页面布局、接口、开发切片或实现进度。

## 1. 产品主线

围绕减少资料整理、背景重复解释、结果核查和稿件搬运成本组织产品：

- **个人材料**：帮助理解用户的参考文档，不是已核实事实库。
- **用户已确认背景**：用户明确核对并同意保存的凝练经历，按人物长期保存和复用。
- **工作区简历**：每个工作区独立维护一份可编辑保存的简历。导入工作区简历不自动进入个人材料库；添加个人材料也不自动建立或替换工作区简历。
- **AI 辅助**：结合工作区简历、工作区选定材料及该人物全部已确认背景对话、追问、提供文字建议，不直接改稿。

收益仍待真实使用验证；用户确认不等于系统完成外部真实性核验。

P0 为基础 MVP 必需能力，P1 为保留但不纳入 MVP 的增强能力。优先级不代表开发顺序；必要保护不能与能力拆开。

| 功能 | 用户可以做什么 | 优先级及依据 |
| --- | --- | --- |
| 登录与人物档案 | 受保护地访问，创建、选择人物，资料互相隔离 | P0；基线 01、02 |
| 工作区与简历建立 | 手动创建名称及方向，导入简历或复制同档案其他工作区简历；同方向可多区且互不覆盖 | P0；03、04、10 按最新导入边界调整 |
| 材料导入与管理 | 上传或粘贴中文纯文本、DOCX、文本层 PDF；查看名称、内容及时间，按名称查找、重命名，查看/下载原件；提取内容可检查修正 | P0；05–07、39 按最新定位调整 |
| 重复与异常提示 | 重复只提示，不覆盖、不比较合并；失败及遗漏明确反馈，不伪造可读或完整内容 | P0；07、39 |
| 工作区参考材料 | 一份材料可多选同人物的工作区作为参考去向，默认不选；各工作区只使用明确选定的材料 | P0；08 按最新多选决定调整 |
| 工作区简历编辑与保存 | 手工编辑、自动保存和重开；失败、冲突及离开时保护编辑并提供复制兜底 | P0；19、20 |
| AI 对话 | 实际接入大模型 API，自然语言提问、连续交流、按需追问及文字建议 | P0；最新 MVP 决定、13 |
| 轻量对话和输入草稿 | 每区一段持久对话及一份输入草稿，重开继续；区分保留记录、重置模型上下文和清空记录 | P0；本轮确认，不做多会话管理 |
| 简历来源查看 | 上传建立简历后，可通过该区来源信息打开/下载导入文件，不加入个人材料库或 AI 参考范围 | P0；本轮确认 |
| 背景提炼与明确确认 | 展示待保存的具体内容及用途，用户明确确认后保存对应部分，不延伸整份材料 | P0；最新决定，覆盖 16、17 整体延后安排 |
| 背景查看、纠正和撤回 | 对话中可查看持久背景，纠正或撤回错误记录；冲突先澄清 | P0；背景整理的必要组成 |
| 全部背景复用 | 同人各工作区使用该人的全部已确认背景，不做相关性筛选，不无故重复确认 | P0；最新确认 |
| 资料使用与失败保护 | 接收方和范围可见，用户选择并主动发送，不另加外发勾选或弹窗；调用有限制，不误报成功 | P0；32、33、35 按最新交互决定调整 |
| 结构化建议对照 | 对照原文、建议、变化、依据和未知 | P1；14、C04，不影响普通文字建议 |
| 建议依赖变化处理 | 材料、背景或原文变化后，相关结构化建议暂停采用 | 随后续建议/写回能力提供必要保护；09 |

## 3. 已确认的 MVP 边界

MVP 包含三条闭环：

1. 资料整理、独立简历建立、编辑保存和再次使用。
2. 工作区简历、工作区选定材料及全部已确认背景支持的轻量持久 AI 对话，保留每区输入草稿。
3. 提炼候选背景、用户明确确认保存、查看及纠正撤回、后续复用。

**核心假设：**管理文档并复用明确确认的背景，能减少查找、重复解释和核对成本。必须实际接入模型并持久保存背景，不能用静态回答或页面临时记忆替代；不预设省时、省钱或完整任务收益成立。

背景确认先用普通对话，不要求 Agent、选择题、弹窗或确认卡。后续可以优化形式，但确认内容、用途和实际结果必须一致。**AI 可经明确确认保存背景，不直接编辑、删除、替换或写回工作区简历。**用户自行判断建议并手工修改。

### 暂不包含的保留需求

| 范围 | 内容 |
| --- | --- |
| 工作区简历补充入口 | 从任意已有档案材料建立工作区简历；未完成导入草稿也不持久保存，离开后重新导入 |
| AI 修改增强 | 专门 JD 管理、结构化对照及授权写回；普通对话可提供岗位要求，参考工作区简历时的发送前保存已纳入 MVP |
| 背景增强 | 选择题、确认卡/弹窗、Agent 编排优化和复杂语义关联；基本确认、纠正撤回及冲突澄清不延后 |
| 持续使用扩展 | 历史稿恢复、任务摘要、正式导出、删除回收恢复、备份恢复 |
| 外部与运行扩展 | 多供应商切换、独立任务管理/取消、联网搜索、局域访问及完整诊断；已有请求状态恢复、防重复调用、资料范围告知和有限调用保护不延后 |

### 排除项与取消方案

- 不建立工作区简历来源绑定或独立化；复制/导入形成独立的工作区简历。
- 不在已有区比较、替换、合并新稿；另一份简历走新建工作区。
- 不做方向模板、复杂版本树、批量派生或强制材料用途分类。一份材料指定多个工作区已纳入 MVP，多份材料的批量操作尚未确定。
- 不要求 DOC、扫描件/OCR、排版还原或 PDF/Word 导出。
- 不复制 Notion 完整功能体系。MVP 用单层列表、名称搜索及最近导入/内容更新排序；材料文本可手动编辑保存。文件夹、标签、归档、全文搜索暂不纳入。

## 4. 核心链路

### A：首次建立并维护简历

登录 → 创建/选择人物 → 创建工作区 → 上传简历或粘贴文本 → 预览文字并按需修正 → 建立工作区简历 → 编辑自动保存 → 再次打开。

导入工作区简历不自动进入个人材料库或成为参考材料；预览修正不确认经历，也不修改个人材料。建立成功后保留上传文件，供工作区来源信息中查看，不随简历编辑变化。未完成导入不持久保存，离开前提醒放弃后需要重新导入，工作区仍待建立简历。

### B：维护另一份目标简历

选择同一人物 → 新建工作区 → 选择起始来源：

- 导入简历：上传/粘贴 → 预览并按需修正 → 建立工作区简历，不自动添加个人材料。
- 复制简历：选择同档案其他工作区 → 只读预览其已保存的工作区简历 → 明确复制后在新工作区编辑。

之后独立编辑保存。只复制简历文本，不带入对话、JD 或辅助材料引用；人物背景本来按人物共享，不通过复制继承。

### C：管理并选择参考材料

选择人物 → 添加个人材料 → 可多选同人物的工作区作为参考去向，也可不选 → 解析反馈和内容查看 → 各选定工作区后续对话沿用 → 按需调整范围。

默认不选任何工作区，不因当前打开某区就替用户选中。多区共用同一份材料，不复制文件；保存与参考设置结果分别反馈。选择不立即外发或调用 AI。材料可含旧信息和不确定描述，不直接升级为已确认背景。

### D：再次使用

登录回到上次可用工作区 → 打开已保存简历、对话和输入草稿 → 继续编辑或对话。未保存简历/材料不承诺关页恢复；已成功保存的对话和草稿支持重开。失败或冲突保护页面内容，不误报成功。

### E：结合资料对话

打开工作区 → 查看模型和资料范围，按需选择 → 主动发送 → AI 回答/追问 → 保存对话并继续交流或手工改稿。不要求先添加材料或填背景表。

不自动搜索或扩大范围；未读取内容不能写成依据。全部背景提供、不做相关性筛选；容量不足明确说明，不静默遗漏。参考工作区简历时先保存再发送，失败不发请求且保留输入；不参考时不受该保存失败阻塞。材料保持手动保存，未保存修改不参与，明确使用已保存文本。

### F：确认并复用背景

AI 从简历、材料或对话提炼候选 → 展示确切内容和保存用途 → 用户完全确认或明确确认部分 → 保存对应内容并反馈 → 对话中可查看 → 后续同人工作区复用。

拒绝、暂不确认或指向不清不保存；纠正后重新明确待保存内容。确认“协助部署”不能扩大为“独立部署”，缺少成果数据保留未知。失败不称已记住；聊天存在不代表背景已持久化。

## 5. 材料、背景与变化规则

### 材料是参考文档

- 正常添加不强制人工检查确认。部分提取有可用文本时允许参考，展示已知遗漏并告知 AI 读取限制，不保证检测全部遗漏；彻底失败不可参考，可重试或粘贴。
- 材料文本允许手动编辑保存，原件不变；保存后各引用区后续使用新文本，不自动调用 AI、改简历或背景。取消放弃未保存修改，失败/冲突/离开时保护输入。
- 展示名称与原文件名分开，重命名不改变正文、原件、参考关系、背景、内容更新时间或排序。原件提供打开/下载入口，粘贴文本无原件；原件不可用但材料文本可读时，文本仍可参考。
- 不再以已确认/未确认作为主要分组或真实性门禁。显示解析状态、导入/更新时间；时间不是有效期，缺失时不编造。
- 只用本工作区明确选定的材料，选定后沿用。停止本区参考不删除文档，不影响其他区。材料变化不自动改简历，也不删除用户独立确认的背景。
- 不自动过期或强制定期重确认。此前“需更新，暂不参考”的全局标记随文档管理方式重新细化，不继续作为已定 P0 门禁。
- 更新后告知 AI 重新读取最新内容，对话继续，不自动重答。停止参考后不再读取发送该材料，但不删除旧消息或独立背景；如需不再携带旧聊天，可明确重置上下文并保留可回看消息。仍参与的简历、材料和背景须单独调整，不承诺模型遗忘或撤销已外发内容。

### 背景是明确确认的记录

- 按人物持久保存，与材料独立，能追溯用户确认的具体陈述；不把整份材料当作确认依据。
- 展示内容与用途、用户明确同意后才写入；普通补充、材料原文、AI 推测、简历保存都不触发静默记忆。
- 全部已确认背景用于同人各工作区对话，不做相关性筛选；可查看、纠正、撤回，不无故重复询问。
- 冲突、含糊或范围扩大先澄清，不静默覆盖；不保证发现所有冲突。历史经历不因时间经过失效，“当前任职”等易变信息有需要时核对。
- 背景纠正/撤回不自动改简历或材料，后续告知新状态，不把撤回内容当作有效背景。在途回答使用旧依据时提示核对，不自动中断或重跑；冲突先区分不同事件、纠正记录和讨论措辞，暂缓后不反复追问或阻断无关交流。

### 轻量对话的范围和保护

- 每区保存一段对话及一份输入草稿，不跨区混用；不做会话列表、命名、检索、分支或任务摘要。草稿只有发送才提供给 AI。
- 用户可保留消息但停止携带此前聊天；也可经明确确认清空记录及草稿，不另存旧会话。两种操作均不改简历、材料或背景，回答期间等待完成再执行。
- 同区一次一条请求，不排队，可提前输入；运行中可离开，结果留在原区。重开查询原请求而非重新收费调用，不做实时协同但防多页面重复调用和静默覆盖。
- 对话记录保存失败保留可见回答，可复制或只重试保存，解决前暂停发送。背景保存失败保留确认内容并直接重试、不重复核实，普通对话可继续。草稿失败不丢输入、不阻塞发送，离开时提醒。任何记录重试均不自动重做模型或背景操作。
- 登录失效保护页面编辑，原页重新登录；恢复后核对状态，不自动重放发送或写入。桌面三栏，窄屏仍可阅读操作，不要求独立移动端产品。

### 外发边界

右侧显示模型接收方、全部背景、可取消的工作区简历参考以及本区材料范围；用户选择并主动发送即发起调用，不另设外发授权勾选或首次发送弹窗。简短说明发送使用上述范围并调用所示服务，详细数据说明按需展开。不能静默换供应商、加入未选材料；背景写入仍必须明确确认，不能被普通发送替代。服务条款核验和真实范围控制仍属技术接入的必要保护。
