# AgentCV 开发计划（MVP 切片）

> 依据 01—04 阶段设计安排开发与验证。目标是每片形成可运行、可独立验证的增量，最终串联完成 MVP。本文不代表任何切片已经完成，也不授权立即执行数据库迁移或外发真实个人资料。本轮编号使用 M00—M09，与历史 S01—S03 区分；历史交付不自动计入本轮完成状态。

## 1. 开发方式与完成标准

### 1.1 按可验证能力推进

**01—04 已确认的设计是本轮开发与验收依据。**以目标能力组织实现，不以旧代码缺什么来补什么，也不要求沿用旧页面、接口、表结构或测试断言。旧实现只有在符合目标设计并经本轮验证后才可复用；不合适的部分可重构或重写，无需为了兼容错误设计增加中间层。沿用已选技术栈不等于沿用现有业务实现。

旧代码、旧数据库和文件先保留隔离，保护已有资料与变更；不默认迁入新系统，也不默认必须通过旧系统全部测试。确有旧数据迁入需求时另列映射、演练和验收任务，不作为当前 MVP 的默认依赖。这一原则不授权删除旧数据或覆盖历史。

每个功能切片包含需要的目标数据库建表/增量迁移、后端规则与接口、前端操作、异常反馈和测试，不按“全部建表 → 全部后端 → 全部页面”的水平层次拆分。M00 建立目标工程与验证基线，M09 是集成验收片，其余以用户可操作的增量为主。

“独立验证”指：在明确的前置切片已通过后，用固定数据和可重复步骤验证本片结果，不依赖尚未完成的后续功能。不表示每片可以脱离数据库、登录或前序能力独立部署。测试可使用受控模型替身验证异常与计数；替身必须标记为测试用途，不能作为真实模型接入或完整 MVP 的通过证据。

不预设工期或完成日期。每片开始前先核查代码和依赖，再细化本片工作；片过大时拆成仍可验证的子片，不以“代码写完但无法演示”作为完成。

### 1.2 统一完成定义

每片交付同时满足：

1. 对应主路径可以从页面操作；基础片有可重复的技术验证入口。
2. 接口、数据迁移和关键并发/失败测试通过，前序受影响能力无回归。
3. 权限、版本冲突、幂等、保存状态和输入保护随能力一起完成，不以最后加固替代。
4. 真实页面行为与 03 一致，浏览器体验检查记录通过情况；自动测试不能替代用户体验确认。
5. 更新接口样例、执行记录、已知限制和下片交接信息，失败证据不删除或改成成功。
6. 没有阻断本片主路径、数据正确性或必要保护的缺陷。未解决问题明确归属，不能隐去后宣告完成。

状态采用“未开始 / 进行中 / 技术验证通过 / 待体验确认 / 已完成 / 阻塞”。只有证据齐全并完成对应体验确认才能标为已完成；不将本计划的初始状态改成现有代码完成度。

## 3. M00：建立目标工程与验证基线

**结果：**按 04 的技术栈和模块边界建立可构建、可启动、可测试的目标工程基础，使后续切片能够直接验证设计要求。

交付范围：

- 建立目标前后端工程结构、业务模块依赖、配置分离和静态资源打包链路；在现仓库内组织，具体目录由目标职责决定，不受旧类和文件布局限制。
- 按 04 建立独立数据库/schema、文件目录及 Flyway 基线；不得连接旧数据空间执行重建，不修改旧环境已应用的迁移。新切片验证从目标空库初始化和本轮增量升级。
- 为 M01 准备认证接入、错误格式、参数校验、版本条件和幂等的最小基础；不提前实现全量业务或抽象通用平台。
- 建立与 01—04 对应的验收用例、合成数据和测试分层，区分单测、数据库/HTTP 集成与浏览器验证；测试能使用隔离资源重复运行。
- 核查并保留 Git 变更与旧运行资源，记录新旧入口/端口/目录，避免误用。旧代码按需评估复用，不以修复旧系统、旧数据迁移或旧测试全绿作为退出条件。
- 建立目标构建、启动、测试和文档检查入口及执行记录模板；已有脚本只有通过新工程验证后才复用。
- 启动服务商/模型能力核验：上下文、超时、计费、数据处理条款、请求幂等、查询和重试支持。未选定时记录阻塞范围，不编造接口能力。

独立验证与退出条件：

- 目标工程可构建并启动打包应用；数据库连接、Flyway 初始化、前后端连通和最小 HTTP 冒烟通过，不用虚假业务页面冒充功能完成。
- 在隔离空库/目录重复运行初始化和测试，证明不会写入旧资源；后续每片验证自己的建表或增量升级。
- 有设计到切片/用例的覆盖清单和可执行验证入口；被复用代码通过新契约检查，旧语义测试不进入新 MVP 验收标准。

## 4. M01：登录、人物、工作区与粘贴简历

**用户结果：**登录 → 创建人物 → 新建工作区 → 粘贴预览修正 → 建立工作区简历 → 编辑自动保存 → 重开可用。

交付范围：

- 三栏基础工作台、空状态、逐层导航和当前归属；无简历/无模型能力处如实显示状态，不放可误用入口。
- 同名人物/工作区允许创建，方向和创建时间辅助辨识；最近编辑时间只反映简历编辑。
- 按目标数据模型建立/演进档案、工作区与简历表；粘贴建立不新增个人材料、背景或参考关系，目标已初始化拒绝覆盖。旧环境简历保留在原处，不默认迁入。
- 简历自动保存、版本检查、幂等、保存中与失败状态；切区先保护输入，失败提供留下/复制/明确放弃。
- 登录错误就近提示；登录过期原页重新登录，保留编辑，重新校验状态，不自动重放写入。后续模块复用该保护。
- 基础键盘、弹窗焦点和窄屏布局随页面完成，不等最终验收才重做结构。

独立验证：

- 通过浏览器完成上述路径；刷新后恢复已保存简历，上次位置不可用有回退说明。
- 两页同时保存仅一个版本成功，另页保留输入；重复建立/保存不产生重复业务结果。
- 跨人物访问和初始化拒绝；纯空格、网络失败、登录失效、复制失败不误报成功。
- 导入未建立离开明确提醒，不声称可恢复；数据库、前端状态及 HTTP 集成测试覆盖关键约束。

**完成边界：**本片只保证粘贴建立，文件与复制由 M02 补齐；右侧尚未接入 AI 必须如实显示。

## 5. M02：文件导入、来源信息与复制简历

**用户结果：**上传 TXT/DOCX/文本层 PDF 预览修正并建立简历，查看来源原件；新建另一工作区复制后独立编辑。

交付范围：

- 按目标契约实现解析，区分完整、部分提取、无文本、不支持、损坏和超限；可复用验证合格的旧解析代码，预览不触发模型。
- 临时上传与业务建立分开，未完成导入不保存可恢复草稿；临时文件有可验证的过期清理。
- 来源文件独立关联工作区，不加入个人材料；通过受保护入口打开/下载，不用文件名拼路径。
- 文件临时写入、正式化、状态与补偿；文本已保存和原件失败分开反馈。
- 同人来源选择、搜索、只读预览和复制确认；来源变化需刷新，目标已建立拒绝覆盖。
- 目标运行入口仅提供本轮设计允许的建立方式，不暴露强制材料确认或已有区替换简历等旧路径；复用旧应用组件时同时检查后端路由，不能只隐藏按钮。

独立验证：

- 合成 TXT、DOCX、PDF 正常路径；坏文件、扫描 PDF、部分提取和超限反馈符合实际。
- 建立后编辑不改来源文件；粘贴/复制没有伪造原件按钮；下载归属和路径穿越防护通过。
- 故障注入覆盖文件与数据库两边失败；清理不删仍有引用或进行中的文件。
- 两区复制后互不影响，不带入材料关系和聊天；来源预览后变化和并发初始化可复现。

## 6. M03：个人材料与多区参考

**用户结果：**不必先建工作区即可添加材料，按需供同人物多个工作区参考，并可编辑文本、重命名及停止参考。

交付范围：

- 独立的个人材料列表/详情/添加入口，不与简历导入混用；默认不选工作区，无用途分类和整份确认门禁。
- 名称搜索、最近导入/正文更新排序、原件入口、重复提示；重命名/浏览不改变正文更新时间和排序。
- 手动保存材料文本，原件不变；部分提取可参考且展示限制，彻底失败不可参考。
- 多区共用同一材料，添加和参考设置结果分开反馈；单区参考调整与范围版本检查。
- 中间预览、材料子列表、返回简历、未保存输入和跨页面冲突保护；选择和停止不调用 AI。

独立验证：

- 无工作区添加、多选/不选、重复同名、跨人物禁止关联、取消参考仅影响本区。
- 文本编辑不改原件、简历或背景；保存失败保留输入，旧版本不覆盖。
- 列表排序、空库与搜索无结果、原件丢失但文本可用分别验证。
- 使用调用计数或无外发配置证明管理操作未触发模型，不把“允许参考”显示为“已读取”。

## 7. M04：真实模型接入与一次异步对话

**用户结果：**在右侧看到服务与资料范围，主动发送后获得真实模型回答；刷新或切区不会重复调用或把回答写到别区。

开始条件：服务商和模型选定，安全后端配置可用，能力/条款核验有记录；真实连通验证先用合成资料，不要求用户提交个人资料来测试。缺凭据时可完成替身测试，但本片真实接入验收仍阻塞。

交付范围：

- 后端模型适配器、配置和错误转换；先一个服务商，无流式/供应商管理页，禁止隐式 HTTP 自动重试和静默切换供应商。
- 数据库请求、消息、输入快照及后台有界执行器；受理原子校验版本/归属/范围/同区状态，短事务与外部调用分开。
- 原子领取、令牌校验、`ACCEPTED/CLAIMED/CALLING` 及结果状态；结果不明不自动重调，轮询恢复原请求。
- 全局受理/执行采用保守的可配置上限，禁止无限积压；结果不明须提供查询及用户明确决定后发起新尝试的路径，不永久锁区。M08 再验证并校准参数，不能在本片先无界运行。
- 右侧范围栏、简历默认参考可取消、所选材料数量及解析限制；背景此时实际为 0，不能以占位数冒充完成背景能力。
- 参考简历时先保存再发送，失败不调用；材料只用已保存文本。固定受理时依据，容量不够暂停，历史预算预留扩展点。
- 材料更新或停止参考后，下次请求使用最新状态并告知变化；受影响的在途回答显示旧依据提示，不自动重答。M07 扩展到背景并组合验证，不将材料保护推迟到 M07。
- 用户消息与回答持久化的最小闭环；回答生成后保存失败仍可见、可复制和仅重试保存，解决前暂停发送。日志从本片起不记正文或凭据。

独立验证：

- 至少一次真实服务端调用从页面完成，记录供应商/模型、结果、耗时和实际可得用量，不保存敏感正文作证据。
- 替身精确计数验证同键重放、两页竞争、查询失败、提交结果不明均不重复外发；不同工作区结果不串用。
- 截获测试替身输入证明未选材料和来源文件没有混入，简历取消参考生效、解析限制随请求传递。
- 模型已返回后注入数据库写入失败，页面仍看到结果并只重试保存；内存暂存重启丢失的边界明确展示。
- 最小重启实验覆盖未外发可恢复、进入 `CALLING` 后不自动重调；没有这些保护不能提前宣布真实调用闭环完成。

## 8. M05：持续交流、草稿和上下文控制

**用户结果：**可连续交流、重开继续，下一条草稿不丢；能分别选择保留旧消息但不再携带，或清空记录及草稿。

交付范围：

- 每区单段对话与单份草稿；分页回看与连续请求使用近期完整交流，不做自动摘要或多会话管理。
- 草稿自动保存、切区/刷新/重登恢复成功部分；保存失败仍允许发送，切走可留下/复制/明确放弃。
- 提交成功只清除对应已发送文字，不误清回答期间新写草稿；发送失败/结果不明保留文字。
- AI 顶部两个独立入口，分隔点、上下文代次与清空的原子处理；不关联供应商旧会话，清空不另存可回看旧档案。
- 回答期间禁用分隔与清空；其他页新增消息、重置、清空或改草稿时，检查变化并保留输入，不自动提交。
- Enter/Shift+Enter、中文输入法、等待状态和焦点验证；登录恢复查询原请求，不重放操作。

独立验证：

- 连聊后重启应用/重登恢复已保存记录，两个区的记录和草稿隔离。
- 替身输入断言分隔前消息不再发送、服务端旧会话标识不沿用；清空后草稿和旧消息不可回看，而简历/材料不变。
- 容量只截取近期完整交流且有说明；必需资料超限不调用，不通过自动摘要绕过。
- 草稿保存失败、旧保存响应晚到、两页编辑、别处清空、回答晚到均不静默覆盖或重建旧上下文。

## 9. M06：背景提炼、确认保存与跨区复用

**用户结果：**普通对话中看到确切候选及用途，明确确认对应内容后，能查看实际背景并在同人其他工作区复用。

交付范围：

- 候选、有效背景及确认记录，绑定人物、候选版本、展示内容和实际用户确认；模型输出不能绕过后端校验直接写入。
- 从真实对话形成候选，支持完全/部分确认，含糊/假设/拒绝/暂缓不保存；修改候选后重新明确最终内容。
- 右侧实际背景数量、中间真实列表和返回入口，不要求卡片或背景表；全部有效背景供同人工作区，不做相关性筛选。
- 背景保存失败保留已确认内容并直接重试，不重新提炼、不重调模型、不重复记录；普通交流可继续，但明确未长期保存。
- 候选与普通聊天、材料确认分离，真实保存结果单独反馈；即使对话记录保存失败，背景结果也不能误报或重复执行。

独立验证：

- 替身回归覆盖部分确认、扩大职责、未展示推断、指向不明、重复确认和旧候选确认；数据库中仅有实际明确确认内容。
- 真实模型走读“协助部署”等合成经历，验证从提炼到自然语言确认再到列表的完整链路，不只用内部 API 造背景。
- 同人新工作区请求包含全部有效背景，其他人物不包含；材料停止参考不删除独立背景。
- 注入背景保存失败后只重试数据库操作，模型调用计数不增；候选过期/目标变化先核对，不写入旧意图。

## 10. M07：背景纠正、撤回和依据变化

**用户结果：**可从列表或对话纠正/撤回记录；遇到新旧描述冲突先澄清，后续使用新状态，在途旧依据可辨认。

交付范围：

- 列表原位纠正、原文和拟修改内容对照确认，支持对话定位；多条可能时先澄清。
- 撤回展示确切内容与影响，成功后更新有效列表/数量，不删除聊天或材料，不提供虚构恢复入口。
- 冲突分为不同事件、纠正记录、讨论措辞和暂缓；暂缓不反复追问，不阻断无关交流。
- 下一次调用告知背景纠正/撤回、材料更新/停止参考，使用最新保存内容与限制，不仅修改界面。
- 回答期间允许改材料/背景，受影响回答提示变更前依据，不自动取消或重跑，仍按本次快照执行。

独立验证：

- 两页纠正或撤回同条背景不覆盖新状态，旧确认与失败重试不能恢复已撤回意图。
- 替身延迟请求期间修改背景/材料，验证旧请求快照未变、有提示，下一条实际输入已更新。
- 四类冲突固定用例和真实模型走读；不能以模型某次回答正常声称能发现所有冲突。
- 撤回后旧聊天里的说法不会无提示继续作为有效背景；停止材料参考不保证语义遗忘，上下文分隔仍可单独使用。

## 11. M08：运行恢复、数据清理与故障验证

**结果：**跨模块失败和进程重启可解释、可恢复，默认运行参数与清理规则有验证依据。此片集中验证组合故障，不用于补做前片缺失的必要保护。

交付范围：

- 对活动请求做分阶段崩溃实验：受理、领取、外发前状态提交、供应商返回、聊天保存之间分别中断。
- 明确 `UNKNOWN` 的用户处理与区内占用解除规则；旧执行器失去令牌不得再次外发或覆盖新尝试，晚到结果不得错写当前状态。
- 验证全局受理/执行上限、拒绝时草稿保护和无无限积压；设定经实测的并发、超时、轮询和容量配置。
- 确定快照、临时文件、幂等记录及失败元数据的保留与清理周期；进行中任务及有效文件不得被清理，过期幂等键不触发旧请求自动重调。
- 安全检查覆盖 Session/CSRF/归属/文件下载、秘密与正文日志扫描、供应商恶意错误文本；错误格式和恢复方式一致。
- 安全重启与发布步骤、配置说明、迁移后核验，测试与真实服务凭据隔离。

独立验证：

- 使用隔离环境、可控替身和调用计数生成故障矩阵；明确“可恢复 / 结果不明 / 不能恢复”而非全部强行重试。
- 数据库不可用、文件缺失、磁盘写入失败和供应商超时后，界面状态、输入保护与重试行为符合 03/04。
- 清理前后核对简历、消息、背景和原件引用，证明没有误删业务数据或未完成任务；泄露扫描无敏感内容。
- 关键 SQL 执行计划与本机负载测试支持所设参数，不把单机测试当成公网高并发承诺。

## 12. M09：完整 MVP 串联验收与交接

**结果：**不依赖内部测试入口即可从页面完成三条 MVP 闭环，形成可复核的功能、可靠性及使用体验证据。

必走场景：

1. 新用户登录 → 建人物/工作区 → 上传预览修正 → 建立简历 → 来源查看 → 保存重开。
2. 复制至同人另一工作区 → 独立编辑；添加材料 → 默认不选 → 多区参考 → 更新/停止参考。
3. 查看实际模型和范围 → 主动发送 → 连续真实交流 → 不自动改简历 → 用户手工修改并保存。
4. 提炼背景 → 明确确认全部或部分 → 查看 → 跨区复用 → 纠正/撤回 → 冲突澄清。
5. 回答中切区并返回 → 刷新/重登恢复 → 草稿恢复 → 分隔上下文 → 清空记录。
6. 两页并发、三类保存失败、登录失效、在途依据变化和未知调用，按各片证据回归。
7. 桌面、窄电脑和极窄窗口操作，键盘和中文选字不误发；中间查看材料/背景时不丢对话或未保存编辑。

退出条件：

- 前序切片技术与体验问题闭环，真实模型端到端路径通过，不能用替身替代整个验收。
- 目标空库初始化与本轮切片间增量升级均可运行，最终 JAR/静态资源打包后 HTTP 与浏览器验证通过。旧系统数据升级不属于默认验收项。
- 输出需求覆盖表、测试结果、已知限制、启动配置和无内部编号的用户操作指南；不再向用户暴露历史冲突主路径。
- 无阻断 MVP 的缺陷；保留的问题只可在已确认排除范围内，不以“下一版修”跳过 P0 必要行为。
- 记录至少一次合成任务的耗时、操作、返工与真实可得费用，作为后续价值对照基线；功能验收不等于已证明省时、省钱或优于网页版模型。
