## 已确认技术选型

| 决策 | 当前结论 | 原因及边界 |
| --- | --- | --- |
| Agent组织 | 单Agent，不做多Agent编排 | 当前操作类型有限，以快速、准确交付及可解释的业务流程为主 |
| AI框架 | 本轮不新增Spring AI、LangChain4j等AI框架，沿用现有模型适配器并实现有限受控操作调度 | 用户明确以交付速度、准确性及学习投入收益为依据，不为技术名词增加框架。后续若工具/模型适配规模增长，或实测表明自维护成本明显更高，再比较；不是永久禁止框架 |

| UI与布局 | Element Plus按需使用，CSS Grid＋Pointer Events＋键盘调整，自建工作台布局 | 不混用多套UI库，不新增全局状态库；具体版本/主题/焦点与兼容性在接入时验证 |
| 数据与恢复 | 现有PostgreSQL/JDBC/Flyway、短事务、版本条件和幂等；可读流批次检查点、复用resume_revision及来源历史 | 不引Redis/消息队列或全量事件日志；参数、迁移、会话与恢复边界需实测 |

## 2. 架构与Act调度

采用单模型、有限类型提议和确定性业务服务。Act不拆成用户可见子模式；不引入多模型反复协商、任意代码/SQL/文件操作或开放式工具循环。

```text
浏览器 POST受理（mode、版本、可选方案起点、幂等键）
  → 短事务校验并固定输入 → 现有worker一次外发
  → 流式适配/可读增量 → 批次持久化 → 浏览器订阅原任务
  → 完整输出校验 → 保存回答及提议（不是应用）
用户按钮/明确自然语言授权 → 业务服务校验 → 短事务执行 → 实际结果
```

Chat不注入操作协议，输出仅作为文本，不解析为变更；服务端拒绝来自Chat的变更指令，不能只依赖提示词。Act允许提出简历方案、背景新增/纠正/撤回。档案/材料删除等仍走已设计的管理界面，不因Act入口统一就默认开放所有自然语言工具。

明确应用/确认优先走本地可识别、绑定已展示对象的命令，避免为“应用方案3”再收费请求模型。含糊或复杂语句若由模型解释，只生成待校验意图，不授予写权限；缺乏确切目标/版本/已展示内容证据则澄清或请用按钮。多目标任务逐项报告结果，已成功子操作不重复执行。

## 3. 模型输出及流式边界

Chat不提供工具定义，直接输出可读文本。Act采用原生Tool Calling：content增量用于可读回答，tool_calls按index/id聚合名称和arguments，完整接收后校验成版本化应用提议。content与参数不能混为一体，不显示原始工具JSON。先以本地和合成真实样例验证deepseek-flash兼容性，不把选型认可当作模型能力验证。若模型只返回工具而无content，由程序展示真实阶段及方案摘要，不自动增加模型调用来润色，不伪造模型正文流。

自定义结构化输出（schema_version、answer、actions）仅为原生工具协议验证不满足时的备选，届时再细化增量解析；不同时维护两套默认链路，不恢复历史强制JSON response_format，不为协议失败自动切换并收费重发。

actions采用白名单类型，例如resume_proposal、background_candidates、background_correction、background_withdrawal；限制条数、文本大小、目标ID/版本，拒绝未知类型、多份冲突正文、截断和未正常完成结果。单次可同时整理背景候选及一份简历方案，但不执行写回；后续调整生成另一个方案。简历输出拟议全文，局部任务后端核查目标范围外未被意外改写；定位不明确先澄清，不执行模糊字符串补丁。

SSE/工具参数聚合必须覆盖分段转义、引号、Unicode、多个tool index及输入上限，只展示可读content，不展示原始JSON、工具参数或隐藏思维。工具调用的正常结束使用供应商tool_calls终态语义，普通正文使用stop；不能把工具终态当文本截断，详细完成条件在契约中固定。格式不合格时保留可安全显示说明并报告未形成方案，不把原始协议降级成普通正文。`max_tokens`当前4096可能不够全文改稿，需明确输出预算和超限提示，不静默截断或自动续费补全。超出已验证上限时拒绝生成该范围，提示用户缩小任务。

官方[Chat Completions参考](https://api-docs.deepseek.com/api/create-chat-completion)列有content/tool_calls增量、finish_reason、usage与[DONE]；本轮仅查文档，尚未真实验证当前模型流式或工具调用。usage可能缺失，不能补造；完成需正常finish_reason及完整协议，收到HTTP200或部分字节不等于成功。实现前先本地模拟协议，再单独限定合成真实调用范围验证，不自动外发用户资料。

## 4. SSE、重连与持久化

沿用MVC SseEmitter，浏览器建议用fetch读取text/event-stream，便于检查401/403、AbortController和显式重连；不增加第三方SSE库。受理仍为有CSRF/幂等保护的POST，SSE为受保护只读GET，绝不通过订阅创建模型请求。保留最终状态GET兜底，不将全站轮询全部改为SSE。

拟议路径：现有requests/{id}下增加`/events?after_seq=N`。事件包含request_id、单调seq、type和payload。示例类型snapshot（可重置正文）、answer_delta、status、proposal_ready、terminal；空行/注释心跳不增加生成进度。终态以已提交业务状态为准，重复事件按seq忽略。订阅检查人物/工作区/请求归属、visible和登录；每次重连及定期检查会话，失效关闭并原页重登。no-store、防代理缓冲，响应头发出前返回正常安全JSON错误。

推荐数据库每请求一条stream_progress，保存已提交可读正文、seq、阶段及partial标识；本机小容量ring buffer仅作增量回放优化，断档时发送snapshot重置，避免无限事件表。建议初始约250ms或4KiB阈值批次提交（任一满足则提交，有单批上限），心跳约15秒，具体以本地负载测试调整。事件原则上在批次提交后发布；DB失败时仍可将内存文字标为volatile展示，seq/持久水位区分，恢复时snapshot核对，不假报保存。

每流接收量/帧长度/解码正文均有上限，初始沿用总接收2MiB；订阅数量、内存ring、发送队列和线程池必须有界。模型接收不直接同步等待慢浏览器写出；慢订阅关闭后恢复snapshot，不能拖住供应商读取。无浏览器订阅时原任务继续，停止等待仍走明确状态转换而非仅关闭SSE。

应用重启：已提交部分可回看并标未完成，CALLING仍变UNKNOWN，不自动续调；未提交尾部可能丢失。完整结果可靠保存前不开放应用。最终事务提交回答、方案/候选和任务终态，随后发ready/terminal。DB失败仅保存重试，内存暂存重启丢失边界保留。

继续当前m00_app和m00_test隔离，Flyway从实际最大版本后追加，不改V1—V10，不新建P2业务库或迁移旧55433库。以下为逻辑增量，实际迁移号待切片决定。

| 增量 | 主要字段/规则 |
| --- | --- |
| 请求与消息 | mode快照、protocol_version、可选base_proposal_id；老记录标LEGACY/UNKNOWN不伪称Chat，不自动执行历史输出 |
| stream_progress | request_id唯一、profile/workspace归属、seq、可读partial_text、阶段/完整性、更新时间；清聊天时清正文 |
| resume_proposal | id、所属人物/工作区/聊天生命周期、request_id唯一、parent_id、title、base_revision、proposed_text、basis_json、row_version、状态、applied_revision；基线全文从不可变resume_revision读取 |
| 历史元数据 | resume_revision补reason、source_request/proposal、restore_from_revision及来源快照引用；旧记录标LEGACY_SAVE不倒造原因 |
| 来源历史 | 不可变来源元数据及file_id，当前指向与各revision可追溯；清理遍历当前及历史引用，跨区复制来源被删除后仍保留描述，不级联删除目标独立稿 |
| 背景候选 | 关联消息、候选版本、展示指纹、选中条目、暂缓/拒绝及纠正来源；部分确认一次提交选中条目，其余不隐式保存；旧消息确认检查目标及事实变化 |
| 对象并发 | profile/workspace元信息版本、人物资料集合版本；删除影响摘要版本；不与正文版本混用 |

方案状态待应用/已应用/已丢弃，依据过期作为独立计算标志。丢弃保存previous状态，恢复时不将曾应用方案伪装成未应用。重命名不改方案内容；应用后再次点击同键返回原结果，不重复创建revision。继续旧方案发送时显式传方案ID/版本及当前正文版本，模型获知旧拟稿与当前稿，不凭聊天自行猜测。

聊天清除同一事务清消息、可读partial、背景候选/操作提议和全部关联方案正文，旧请求保留最小幂等墓碑；已应用正文及独立历史不删。不能因proposal外键导致历史稿级联删除，可保留非强制引用标识。仅上下文分隔不删方案。operation当前会缓存正文响应，需按对象/生命周期清理敏感响应或改存最小结果引用，不能只隐藏UI仍留正文备份。

历史先保留现有所有revision，不自动裁剪旧稿，也不再为每次应用复制一份已有旧正文；列表优先重要操作，可分页查看。保留量/清理以后依据体积设计，容量不足明确反馈，不静默删除用户方案或成果。

## 6. 写入、替换、删除及锁

应用服务短事务：检查Act授权、对象可见、已展示方案ID/版本/内容指纹、expected_current_revision、依据版本、无活动写入阻塞 → 锁定 → 幂等检查 → 新增revision与原因 → 条件更新当前指针 → 标记方案曾应用 → 操作结果提交。模型不传SQL，不信任浏览器提供的新全文代替已保存方案。恢复也是新增revision，版本永不倒退。

自然语言确认若经过模型解释，不在当前CALLING中直接执行；先保存待确认意图，或在该请求完成后以独立已授权操作执行，避免绕过“运行期间暂停写入”。背景更改同样调用业务服务。各步事务独立且结果可查，不用覆盖跨网络调用的大事务。

替换和恢复将正文、来源快照指针、上下文分隔、版本更新置于同一事务。上传文件正式化仍是事务外可重试阶段，文本成功/文件待就绪分别报告；历史引用避免旧原件被当孤儿删除。AI应用保留当前来源，reason另记AI_APPLY，避免把生成稿伪称上传原文。

锁顺序必须统一改造：全局受理锁（仅需要时）→profile→工作区按UUID排序→对象行/请求行。当前send/persist是workspace后profile，不能只在新接口改相反顺序。所有相关材料、背景、正文写入与删除采用同一guard，人物共享修改检查该人物所有受影响活动请求；与受理共用父级锁防检查后插入竞态。草稿保存例外仍可进行，其他区并发通过共享资料影响范围约束，不默认扩大为多实例。

删除采用数据库业务数据硬删除及最小删除操作墓碑，无回收站；影响预览返回名称/版本和关联计数指纹，确认事务再核对并拒绝变化。相关ACCEPTED/CALLING/SAVE_FAILED阻止删除；UNKNOWN明确风险确认后可解除，worker最终写入检查对象存在及请求状态，不能重新插入。删除幂等重放需专用已删除对象检查，不能照搬write先访问对象导致永远404，也不能通过墓碑泄露其他对象。

文件不在业务事务内直接删除；提交引用移除后由清理在宽限期回收，DB不可读时保留。删除引用材料时更新受影响scope版本；处理复制来源外键、背景确认外键、方案/历史引用及operation缓存，测试所有依赖后再定义实际删除顺序。

## 7. 接口与前端建议

| 契约增量 | 核心规则 |
| --- | --- |
| POST conversation | 增mode、base_proposal_id/version、已知当前版本；mode为请求固定值，历史消息保存实际模式 |
| GET requests/{id}/events | 只读SSE，after_seq，必要时snapshot重置；GET原状态兜底 |
| GET/POST proposal子资源 | 分页查看、重命名、丢弃、恢复、prepare-review、apply；写操作CSRF/幂等/版本；review绑定已展示内容，不承诺机器能证明人真正阅读 |
| GET resume/history、POST resume/restore、resume/replace | 展示/版本条件/幂等，重要操作metadata；恢复不改旧revision |
| 管理PATCH/DELETE及影响预览 | 元信息版本、关联影响版本，服务端复核输入名称与对象，专用删除墓碑 |
| 背景候选GET/confirm/defer/correct | 消息关联、部分选择、版本校验、暂缓不重复催促；纠正后重新展示 |

前端保持Vue/TS，拆TaskStream、ProposalList、ResumeCompare、BackgroundReview及WorkbenchLayout组件/模块；采用Element Plus按需引入按钮、菜单、表单、对话框等通用控件，工作台用CSS Grid及Pointer Events/键盘分隔控件自建，不新增全局状态库。统一主题并回归原有焦点、输入法和未保存保护，不能因换组件丢失行为。布局比例和工作区mode偏好只存版本化localStorage，不放凭据或资料正文；请求mode仍以服务端快照为准。读取设置失败可回退默认。

对比采用jsdiff（diff包）计算行级差异，对变化段按需做字符级突出，Vue自建左右对照与同步滚动，窄屏切换，文字/标记辅助色彩。限定输入大小与计算预算，超大/极端输入退回整块对比并说明；验证中文、重复行及长段落，不依赖英文分词。暂不引入Monaco等完整编辑器。使用Vue文本节点，不通过innerHTML渲染模型/Markdown原文。新增diff/Element Plus的准确版本、Node/Vue/TS兼容性、许可证及锁文件在接入时核对，本轮未安装依赖。

Markdown复用ResumeParser的严格UTF-8/BOM、256KiB、控制字符与预览校验，增加.md/.markdown白名单，简历及材料路径一致；不是Markdown排版引擎，不新增文件执行权限。扩展名与可解码内容共同校验，不信任MIME。

本轮仅代码/文档核查，未实现、未压测、未调用真实流式模型；以下为后续验证目标：

- 本地HTTP模拟拆分UTF-8/转义、多个data帧、CRLF、usage-only、异常finish、缺终止、慢流、头前超时、超限及断流；解析错误不重发。
- SSE多次重连、after_seq重复/断档、snapshot、慢订阅、会话失效、无订阅继续、DB失败与重启；计数证明只调用一次，部分结果不能应用。
- Chat恶意输出操作、Act模糊确认、旧方案版本、依据变化、相同幂等键、跨人物对象、双页竞争；应用与revision原子一致。
- 多方案回看/丢弃恢复、背景暂缓/纠正/部分确认、清聊天与独立历史、缓存正文清除、旧原件保留、删除全部依赖与迟到结果。
- m00_test空库初始化和P1快照升级；不改正式库，业务升级前完成备份恢复演练及已知可用版本归档。
- Playwright覆盖模式/草稿、流式滚动、对比弹窗、方案列表、拖动与键盘、缩放窄屏、输入保护及真实POST内容。真实供应商验证单列合成数据与费用范围，不以本地测试替代。

技术选型已确认，下一步进行局部协议与组件验证、细化工具/事件DTO、事务和迁移契约，再冻结[05切片计划](05_开发计划.md)。无需重复询问已确认的选型；验证若导致业务、费用或能力边界变化，记录证据后明确讨论。
