# P2 关键契约与预验证

状态：技术选型已确认，本文将关键机制细化为开发契约草案。2026-11-25本地协议实验通过；真实供应商、生产解析器、数据库恢复和浏览器流式均未验证。承接[04技术方案](04_技术方案.md)，06是契约附件，不新增一轮需求设计，也不替代05计划。

## 1. 操作与授权

请求固定mode=CHAT/ACT、protocol_version=1、request_id、人物/工作区、当前正文和资料版本；模式在受理后不能修改。Chat无工具定义，服务端也不接受其输出提议。Act第一版仅暴露四种提议工具，不提供直接写库工具：

| 工具名 | 参数主体 | 后端附加/校验 |
| --- | --- | --- |
| propose_resume_change | title、scope（FULL/EXACT_RANGE）、proposed_text；局部另有base_start/base_end及old_text | 绑定受理时workspace、base_revision、basis和可选parent；局部按固定文本偏移逐字校验old_text及范围外内容，定位不清先问，不做模糊匹配 |
| propose_background_entries | items：确切文本、来源于本轮补充的简短说明 | 每批最多8项、每项沿用1000字限制；归属与候选ID由后端生成，不将来源说明当真实性认证 |
| propose_background_correction | background_id、expected_version、old_text、new_text | 校验当前人物、版本及逐字旧内容，形成待确认提议 |
| propose_background_withdrawal | background_id、expected_version、old_text | 同样只形成待确认提议，不立即撤回 |

完整JSON对象、不接受额外字段；工具最多4个/次，其中简历方案最多1份。名称/参数类型、输出大小及冲突组合不合格则拒绝对应提议，保存可读回答和明确失败说明，不执行有效部分写入或自动再调用模型。参数限制属于应用层schema校验，不依赖供应商strict模式。最终schema文件和错误DTO在相应切片实现。

简历方案审阅接口返回proposal_id、proposal_version、base_revision、current_revision、content_hash与短期review_token。token由后端绑定当前登录会话和确切内容；它证明展示对象绑定，不证明人确实读过。应用携带token、expected_current_revision、幂等键。自然语言本地明确命令转换为同一业务操作；“确认”同时可能指背景/简历或多方案时先澄清。不要每次普通讨论都弹授权。

旧方案继续修改显式提交parent_id/version；模型不能自行更改其归属或父方案。正文/依据变化时允许回看和选作新起点，不接受旧token直接覆盖。局部offset基于服务端固定字符串坐标（具体采用Unicode code point索引，前后端统一转换），不沿用未约定的JS UTF-16偏移。

## 2. 模型流与完成

content增量进入可读正文；tool_calls按index累计id/name/arguments，只有完整终态后生成方案。参数不进入正文、不作为隐藏思维展示。允许content为空的纯工具响应，程序显示真实状态和完成摘要，不伪造token流、不自动付费补总结。

普通输出要求finish_reason=stop，含工具要求tool_calls；另要求收到[DONE]、所有参数为完整对象、未越限、没有终态后的额外业务帧。usage可以在choices为空的帧中出现，也可以缺失。length或缺终止不能形成可应用提议。实际供应商终态若不同，先记兼容性证据再调整，不因HTTP200就判成功。

输入字节严格UTF-8增量解码，SSE支持LF/CRLF、注释和多data行，网络块不等于事件块。总接收2MiB为当前基线；实验单帧64Ki字符只是实验限制，正式限制应依据最大正文/工具参数和供应商分块方式确定，不能把可接受的整稿工具帧误拒绝。网络读总期限和取消须在生产gateway实现，本地InputStream实验不验证读取期限。

## 3. 浏览器事件

POST仍按现有API受理并返回202和request_id；GET请求下events?after_seq=N只订阅，不产生外发。普通GET原任务可返回可读正文快照和保存水位。示例：

```json
{"request_id":"合成示例","seq":12,"type":"answer_delta","payload":{"text":"新增文字","durable":true,"durable_seq":12}}
```

| type | 必要载荷与语义 |
| --- | --- |
| snapshot | 完整当前可读text、durable_seq、partial、execution_status、record_status；替换页面累计文本，不能再追加一遍 |
| answer_delta | text、durable与durable_seq；按seq去重，缺号重新获取snapshot |
| status | 明确的实际阶段，不能展示虚构百分比或把心跳当推理进度 |
| proposal_ready | 已可靠提交的proposal ID/version，可打开审阅；不能仅靠此事件执行应用 |
| terminal | execution_status、record_status、partial、可用proposal ID及安全错误码；保存失败与模型失败分开 |

seq按原任务单调递增，进程内volatile尾部与持久水位分开；每次新订阅先发snapshot作为恢复基线，后续发增量。生产实现须在同一快照/订阅同步边界注册订阅并捕获seq，避免查询快照到注册之间丢事件；允许重复，由客户端去重。重启后旧连接关闭，读取持久snapshot并结束遗留任务，不续调。已完成且seq未变化时仍能返回终态快照，不无限等待新事件。

连接错误进行有上限退避，401/403停止重连并原页登录；普通连接恢复不重新POST。任务终态停止重连。明确“停止等待”调用已有业务状态接口，关闭fetch本身不冒充取消模型。慢订阅和发送队列上限在本地负载实验固定，不阻塞供应商读取。

## 4. 写入及生命周期

应用事务：统一锁顺序、对象可见性/ACT和review校验、操作幂等、当前revision/资料依据检查、新revision、当前指针及proposal应用状态、最小操作结果一起提交。检查要在锁内重做，失败全部回滚。幂等重放查询原操作结果，不再以旧正文版本拒绝已成功操作；仍先验证访问权限。恢复新增revision而非倒退；替换/恢复与来源、上下文边界同事务。

草稿保存允许运行中继续；关联正文、背景、材料等写入执行统一活动任务guard，不能只禁用按钮。确认背景等局部成功和简历提议失败分别反馈，模型请求不包住数据库长事务。

proposal与聊天清除同生命周期，当前正文/revision独立；清除包括相关候选、partial及敏感operation缓存，不只是visible=false。历史来源文件加入引用集合后才允许替换上线。删除影响版本在确认时重核，UNKNOWN经明确风险解除后才可删，迟到结果不得重建对象。
