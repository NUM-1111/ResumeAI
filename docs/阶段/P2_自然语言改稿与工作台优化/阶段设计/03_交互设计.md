# P2 交互设计

状态：用户已逐组认可模式、多方案对比、主动背景确认、布局、替换恢复删除及关键异常行为，主要文字交互讨论已收束。具体原型、尺寸、视觉样式与提示语待验证；恢复能力及状态契约须由技术设计和测试落实，不是已实现或已验收页面。承接[产品设计](02_产品设计.md)。

## 已确认的异常交互与收束

以下异常行为已获用户认可：

| 场景 | 页面反馈与恢复规则 |
| --- | --- |
| 流式暂时断线 | 保留已显示文字，提示连接中断、正在恢复查看，重连原任务，不创建新调用 |
| 最终生成失败且仅有部分文字 | 标记回答未完成，可复制；半截方案不可应用，新尝试由用户主动发起并提示可能收费 |
| 停止等待 | 保留已显示内容，说明服务商可能仍处理或收费，不显示为已取消生成 |
| 完整结果记录保存失败 | 保留回答及可用方案，提供重试保存/复制，不重调模型；未解决前暂停新发送，尚未可靠保存的方案不视为已可应用 |
| 应用、替换或恢复保存失败 | 保留方案或预览，正文不提前显示成功，重试已有操作而非重新生成 |
| 提交结果不明确 | 提示正在核对，查询原操作，不靠重复提交判断是否成功 |
| 正文、背景或材料变化 | 保留旧方案可回看，标明需核对，暂停直接应用；用户主动决定是否基于最新资料生成 |
| 登录失效 | 原页登录，保留输入和已显示内容，恢复后核对状态，不自动重发或写入 |
| 其他页修改或删除当前对象 | 提示实际变化，保护本地文字，提供复制与返回可用页面，不静默覆盖 |

多步任务分别反馈实际结果，某步失败不冒充全部成功或全部失败；只重试失败部分，不重复已成功操作。错误就近呈现、不反复弹窗或抢焦点；需要选择、确认或未保存内容处理时再打开对话框。

页面可见不等于可靠保存。仅当前进程暂存时明确关闭/重启可能丢失，提供复制；实际持久化、重连回放及进程恢复边界在04技术设计明确并验证，不把上述交互目标写成已有能力。

下一步核查代码并形成技术方案，结合线框或页面原型验证布局、差异显示与视觉细节；技术或原型若需改变已确认业务行为，应明确记录并再讨论，不静默扩大范围。

## Chat与Act模式

最新用户决定覆盖此前“不设改稿模式”“中间切换预览”“只保留一份方案”的建议。

Chat用于纯讨论和建议，不创建背景变更或简历方案，不执行写入，也不反复追加改稿说明。Act用于更新个人背景及通过自然语言修改简历；背景和简历分属两类数据，授权分别明确。选Act不表示授权任意写入。

以下模式行为已获用户认可：

- 工作区首次默认Chat；切换入口放在右侧输入区附近，当前模式始终可见。
- Chat/Act共用该工作区一段聊天记录，消息附简短模式标识。Act可以利用仍在有效上下文中的Chat讨论，但背景保存与简历应用仍须明确确认。
- 切换保留输入，不自动发送、执行或触发模型调用。
- 任务运行期间锁定本次模式，暂停新发送及写入操作；允许阅读、滚动、查看既有方案和编辑下一条草稿。查看不表示可以应用，结束后再切换或手动发送。
- 刷新后恢复该工作区上次选择的模式，不重新执行已完成操作。

运行期间暂停写入的规则覆盖此前P1允许在回答期间更新材料/背景的交互；本阶段先不提供这种并行操作。其他工作区的并发范围、模式偏好的持久化方式和跨页规则在技术设计中收口。

本阶段不支持提交/修改期间继续发送新聊天或并行操作，可编辑下一条草稿，结束后手动发送。后台任务是否异步是技术问题，与此交互限制分开；刷新或断线仍查看原请求，不重新调用模型。

## Act中的主动背景整理

用户不需要主动下达更新背景命令。Act可以在改稿时针对职责、项目范围等必要事实追问，待用户说明足够清楚后，集中展示拟保存内容，例如：“你刚才说明：在项目A中负责订单接口，部署仅为协助。是否保存到当前人物的个人背景，供该人物后续各工作区对话复用？”

支持确认全部/部分、纠正、暂不保存、拒绝；实际保存后才反馈成功。保存背景不自动修改简历，应用简历不自动确认背景。暂不保存不阻断当前改稿，不就同一已拒绝或暂缓内容每轮询问。Chat下不主动整理持久候选；切换Act后若要利用此前聊天，仍需明确展示内容和确认，不把切模式当作保存授权。

以下主动背景确认交互已获用户认可：

- 在Act本轮回复末尾展示待确认区，不自动弹窗；明确所属人物及供同人物各工作区后续对话复用的用途。与简历修改方案分别展示、分别授权。
- 条目默认勾选，只有用户点击“确认保存所选”或明确自然语言确认才保存；支持部分选择。条目较多时可折叠展开，但确认内容应能完整查看，不因折叠扩大授权。
- 根据明确新事实、纠正或一轮项目澄清完成触发，尽量集中整理，不按固定轮数询问；措辞调整、假设、重复或不清楚的信息不急于保存。任务必需事实可追问，丰富背景的非必需问题不强迫回答。
- 提供“纠正内容”“暂不保存”。暂缓后收起确认区，消息可回看，不保存有效背景、不阻塞改稿；同一内容不反复催促，有实质新信息或用户主动要求时再处理。
- 纠正在原处展开编辑，完成后展示最终内容，再确认保存；自然语言也可明确纠正并确认对应条目，指向不清先澄清。用户可返回旧消息处理，但内容、目标或版本变化时应核对，不执行过期确认。
- 与已有背景冲突时展示新旧内容，询问“纠正原记录/另一项经历/暂不处理”，不预先判定。实际成功后简短反馈保存数量或更新结果，不弹重复成功窗口；失败保留确认内容，只重试保存，不重新调用模型。

背景整理不是每次改稿或应用前的必经关卡。具体尺寸、折叠阈值及提示语在原型中验证，不改变上述行为。

## 自然语言改稿与对比弹窗

Act下提出要求 → 右侧流式显示正在进行的内容 → 完整方案生成 → 点击右侧“查看修改” → 中间区域弹出左右对比 → 确认应用或关闭继续讨论 → 保存成功后关闭弹窗，中间直接显示修改后的正文。

左侧显示方案生成所依据的未修改内容，右侧显示拟修改内容；用颜色及删除线、增删标记等突出差异，不只靠颜色。用户已认可弹窗只读、整份应用，不提供逐行接受或弹窗内编辑；通过聊天调整，应用后可手动编辑正式正文。左右默认同步滚动，可关闭同步；窄屏切换“修改前/修改后”，不强挤双列。底部提供关闭、基于此方案继续修改、应用这版修改；关闭不丢弃方案。具体尺寸待原型验证。

应用成功不额外弹出重复确认或强提示，保留正常保存状态；只有实际保存成功才更新正文，失败保留方案和必要错误提示。自然语言“应用”与按钮效果一致，指向具体已展示方案，不能绕过同样的授权和版本保护。

普通聊天不改正文。当前方案指向不清或正文已变化时先核对；不能仅凭模型口头“已修改”反馈成功。初期整份方案应用，不支持逐行勾选；不满意可继续调整或应用后手动编辑。恢复旧稿也需预览、明确操作及并发保护，不静默覆盖当前编辑。

## 多方案与聊天生命周期

允许保留多个改写备选，可随时从聊天关联入口查看，选择旧方案作为继续修改的起点，或丢弃某个方案。只要未清除聊天，方案应能持久回看；不只保存在页面内存中。调整生成新的备选，不能静默覆盖用户保留的旧方案。

以下方案管理行为已获用户认可：

- 聊天对应消息下提供方案名称、状态、查看对比、基于此方案继续修改及更多菜单；聊天顶部有统一“方案”列表入口，按名称、生成时间和状态查找，无需翻聊天。
- 方案自动命名且可重命名；初期不增加收藏、文件夹或标签。
- 点击继续修改只选择起点、不调用模型，输入区上方显示所选方案，可取消选择；用户发送要求后生成新方案，失败也保留旧方案。
- 状态为待应用、已应用、已丢弃。“已应用”仅表示曾应用，不意味着仍是当前正文；版本或依据变化另显示“需核对，暂不能直接应用”，不自动删除或重新生成。
- 丢弃后默认从备选列表隐藏，可在已丢弃列表恢复；清除聊天才一并清除关联方案。此为备选方案管理，不扩展为档案、工作区和材料的通用回收站。

旧方案可回看或作为新修改起点，不保证可直接覆盖最新正文；需展示原始对比基线，并在当前版本或依据变化时暂停应用，要求核对或主动生成新方案。清除聊天同时清除关联方案，已应用正文及独立旧稿记录保留；仅“不携带此前聊天”不删除方案。备选管理不是已应用简历的历史版本树，两者分开。

## 流式与恢复查看

回答逐步显示；改稿说明或可读内容可逐步展示，完整方案校验后才开放应用。不能把内部JSON直接展示为最终阅读体验。断线、刷新或切区后关联原任务，不重新收费调用；部分回答标未完成，不作为可应用方案。滚动阅读不被持续强制拉回底部，具体跟随和“有新内容”提示待原型确定。

## 布局

保留三栏，左栏可收起；右栏默认增宽、改善字号行距，正文有效利用可用高度，主要编辑区和聊天独立滚动。栏间拖动、记住本机宽度、可重置；空间不足折叠而非挤成细栏。键盘调整、最小宽度与缩放范围需原型确认，不在此锁定像素。

参考范围默认简要摘要，例如“当前简历 · 3份材料 · 8条背景”，详情和选择收进菜单或展开区；显示实际数量和接收模型，选择不冒充读取。按钮、加载、成功、失败及危险操作统一呈现，保留焦点和未保存输入保护。

## 已确认的工作台布局细节

用户已认可以下规则，覆盖前文仍待确定的对应布局行为；尺寸和视觉样式由原型验证。

- 顶部保留人物、工作区与必要全局操作，下方工作台利用剩余窗口高度。左导航、中间正文、右侧消息独立滚动；中间标题/保存状态和右侧输入区保持容易操作。编辑区随可用高度伸展，缩放后按实际空间重排。
- 两条栏间分隔线可拖动，设置最小宽度；支持键盘调整、双击恢复该处默认宽度，以及恢复默认布局。本机记住布局，刷新恢复；左栏一键折叠，右栏默认较P1增宽，中间保住阅读宽度。
- 右侧顶部显示模型、方案入口、更多菜单及一行实际参考范围摘要；管理入口按需打开资料面板，包含简历开关、材料选择与背景数量/查看入口。默认不常驻长资料列表，未参考和零数量如实表达。运行期间只可查看，不可修改。
- 中间查看材料或背景保留右侧对话和输入，提供返回工作区简历入口，保护未保存编辑。对比弹窗打开后背景不参与操作，关闭返回原位置；弹窗优先保证对比可读宽度。
- 流式内容仅在用户位于消息底部时自动跟随，向上阅读后不强拉到底，提供有新内容/回到底部入口。输入框适度增高，到上限后内部滚动，模式和发送/停止等待位置稳定；停止等待不宣称供应商取消。
- 较窄窗口先折叠左导航，正文与聊天并排；极窄时切换简历与资料/AI对话视图，保留编辑、草稿和原任务，不切换工作区。配色、字号、圆角和具体断点通过原型检验。

## 导入、替换与删除流程

以下细节已获用户认可：

- 中间正文更多菜单提供“替换简历”，支持上传、粘贴或复制同人物其他工作区已保存稿件。选择新稿、预览修正、查看新旧对比后确认；说明旧稿进入历史，材料/背景/聊天保留，后续不携带替换前聊天。成功更新正文及来源并显示上下文分隔。旧方案可回看但不能直接覆盖新稿。有未保存编辑先保存，失败/冲突不继续。
- 历史记录展示时间、操作类型和简短说明，选稿与当前稿对比后明确恢复。恢复前保留现稿；恢复不删聊天、材料、背景，设置新的聊天上下文边界，中间显示恢复正文，不重复弹成功窗口。历史稿与备选方案分开管理。
- 对象旁更多菜单提供人物名称、工作区名称/方向及材料名称修改，采用小弹窗或原位表单，保存/取消明确。同名不合并，失败保留输入；修改名称或方向不自动调用模型、改简历或改变参考关系。
- 材料删除用普通确认，说明从材料库移除并解除工作区引用，独立背景及简历不变；工作区与人物删除要求输入对象名称确认，并展示方向/创建时间等辨识信息。工作区删除覆盖其简历、历史、聊天、草稿、备选及参考关系，不删除人物材料背景；人物删除覆盖全部下属数据。提示无通用回收站、界面无法恢复，不承诺撤回供应商已收内容或立即物理擦除全部副本。
- 删除正在查看的材料返回材料列表；删除当前工作区返回该人物工作区列表；删除当前人物返回人物列表。非当前对象删除不改变工作位置。失败保留当前状态，不假报成功。
- 关联任务运行期间删除、替换和恢复不可用并解释原因；UNKNOWN先按明确风险确认及任务解除流程处理，不能无限等待。迟到结果不得重建删除对象或覆盖新稿。具体状态契约在技术设计收口。

Markdown与现有格式共用预览修正路径。替换：选择新稿 → 预览 → 确认替换 → 保留旧稿并保存 → 显示上下文边界。失败保留输入与原稿，不假报成功。

档案、工作区、材料的菜单提供适用管理操作；删除前显示对象及关联影响，取消不改变，成功后导航到可用对象。活动任务、删除确认后关联变化、跨页修改等组合规则需技术设计收口；不增加通用回收站承诺。
