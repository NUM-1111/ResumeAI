# AgentCV 接口约束与验收设计（草案）

> 依据R01—R11及已确认设计策略。Spring JDBC、Flyway、Spring Security、后台有界执行与状态轮询、来源绑定机制已确认；精确版本与具体实现未验证。本文是接口目录、关键字段与测试设计，不是完整OpenAPI或可执行DDL。AT01—AT21全部未执行。

## 1. HTTP公共契约建议

- 基础路径`/api/v1`，JSON字段camelCase；UUID、修订号和带时区时间按07文档约定。文件上传用multipart，导出返回UTF-8纯文本。
- 身份来自服务端会话。URL中的profileId/workspaceId与子对象必须逐层核对；跨档案访问按不可见处理，不能仅靠页面隐藏。
- 写操作携带CSRF信息。创建、采用、恢复、删除等可重复变更携带`Idempotency-Key`；保存等写操作也按07幂等契约处理。相同键不同载荷返回冲突。
- 错误结构：`code`、`message`、`requestId`、可选`operationId`和`nextAction`。不返回服务器路径、密钥或堆栈。成功返回实际结果，不能只返回“请求已收到”而标成已保存。
- 201表示对象已创建；202表示已受理的异步任务，需查询终态；204用于无正文成功；400参数错误、401未登录、403权限/CSRF拒绝、404对象不可见、409状态/版本冲突、413超限、422内容不可处理、503暂不可用。预算耗尽是运行终态原因，不冒充HTTP网络错误。
- 列表使用有界分页和稳定排序，响应包含下一页游标；不得无界返回全部简历正文/历史。页大小上限为配置参数。

## 2. 接口目录（待详细字段评审）

以下路径均相对于基础路径；P=`/profiles/{profileId}`，W=`P/workspaces/{workspaceId}`，所有缩写必须在实际接口规范展开。

| 模块 | 方法与路径 | 主要请求/结果及校验 |
| --- | --- | --- |
| CSRF | GET `/csrf` | 未登录可取token、headerName；Cache-Control: no-store；登录/退出后重新获取，token不进URL/日志 |
| 会话 | POST `/session`；GET `/session`；DELETE `/session` | Spring Security会话登录/查询/退出；凭据不回显，写请求带CSRF；登录后更换会话身份标识 |
| 档案 | POST/GET `/profiles`；GET/PATCH `P` | 创建、分页列表、详情、名称编辑；PATCH带expectedVersion，不在此批量确认事实 |
| 工作区 | POST/GET `P/workspaces`；GET/PATCH `W` | 创建名称与方向；初建无简历时标为待初始化；方向/目标变化需推进版本 |
| 选定起始稿 | POST `W/resume/initialize` | sourceType为WORKSPACE_CURRENT/MATERIAL_REVISION/IMPORTED_REVISION，携带来源ID与预期修订；形成独立稿；禁止跨档案 |
| 材料上传/粘贴 | POST `P/material-imports` | 文件或文本二选一，材料类别、可选更新目标与expectedRevision；返回importId及状态，不把受理当解析成功 |
| 导入状态/检查 | GET `P/material-imports/{importId}`；POST `P/material-imports/{importId}/confirm` | 提取结果、已知异常、重复提示；确认文本与可选明确引用区；保留两份/比较更新/取消须显式决策 |
| 材料读取 | GET `P/materials`；GET `P/materials/{materialId}`；GET `P/materials/{materialId}/content` | 分页元数据、修订文本、受控原件下载；服务端storageKey不输出 |
| 材料引用 | POST `W/material-references`；POST `W/material-references/{referenceId}/revoke` | 指定已确认修订、expectedVersion；重复引用不生成两个有效关系；撤销推进上下文并暂停依赖建议 |
| 新稿比较 | POST `W/resume/comparisons`；GET `W/resume/comparisons/{comparisonId}` | 当前基础修订与已确认候选材料；返回可定位差异及比较状态；比较不更新事实 |
| 新稿采纳 | POST `W/resume/comparisons/{comparisonId}/apply` | 整体替换或明确选定差异ID；校验基础修订后原子落稿并保留历史；另建区走初始化，材料仅保存不调用apply |
| 当前稿/历史 | GET/PUT `W/resume`；GET `W/resume/revisions`；GET `W/resume/revisions/{revision}`；POST `W/resume/restores` | 保存text、expectedRevision、clientEditSequence；恢复携带历史修订与当前预期版本，创建新修订 |
| 独立文本稿 | POST `W/resume/independent-copies` | 明确将当前已保存文本作为新当前修订；解除来源材料绑定，保留历史出处；不改辅助引用或事实 |
| JD | POST/GET `W/jds`；GET/PATCH `W/jds/{jdId}` | 文本或已确认材料来源，更新保留可区分修订；不自动参与分析 |
| 分析目标 | PUT `W/analysis-target` | mode、明确所选JD修订集合或方向、expectedVersion；mode与数量匹配，不启动模型 |
| 任务 | POST `W/tasks`；POST `W/tasks/{taskId}/turns` | userMessage、expectedResumeRevision、targetVersion；页面先完成自动保存；外发授权不满足则停止，不静默调用 |
| 运行 | GET `W/tasks/{taskId}/runs/{runId}`；POST `W/tasks/{taskId}/runs/{runId}/cancel` | 查询运行状态/失败原因/过期状态；取消不保证撤销供应商远端计费，不接收迟到结果为可采用建议 |
| 建议 | GET `W/tasks/{taskId}/suggestions`；POST `W/suggestion-decisions` | suggestionId及version、选中itemIds、ACCEPT/REJECT、expectedResumeRevision；ACCEPT事务/幂等/依据检查；拒绝不改稿 |
| 背景事实 | GET `P/facts`；POST `P/fact-statements`；POST `P/facts/{factId}/corrections`；POST `P/facts/{factId}/withdrawals` | 保留用户原始陈述、expectedVersion；抽取为候选，含糊/冲突先追问；用户清楚陈述无需额外逐次确认清单 |
| AI任务摘要 | GET `W/tasks`；GET `W/tasks/{taskId}`；POST `W/tasks/{taskId}/summary-retries` | 目标、公开判断/依据/未知、实际操作结果及变化标记；补记失败摘要不重做模型任务或写回 |
| 搜索 | POST `W/search-requests` | 用户明确请求、限定query、目标版本；隐私检查后发送，返回结果/失败及来源时间；生成模型不得自由直接调搜索 |
| 外发授权 | GET `P/disclosure-consents`；POST `P/disclosure-consents` | supplier、用途、明确资料范围及授权说明版本；授权不等于文件引用，扩大范围/切换供应商需重新处理 |
| 删除预览/执行 | POST `P/deletion-previews`；POST `P/recycle-operations` | 类型/对象ID；预览返回impactVersion与关联对象，执行携确认和预览版本，变化则重新预览 |
| 回收站 | GET `P/recycle-entries`；POST `P/recycle-entries/{entryId}/restore` | 有效档案和已回收档案均须可经授权入口管理；首轮不自动永久清理，不暴露无检查的清空接口 |
| 操作查询 | GET `/operations/{operationId}` | 仅当前操作者可见且检查归属；响应丢失后查询实际结果，不重新执行 |

回收档案的恢复入口必须允许选择已回收Profile，但除回收管理外不得让其子对象恢复正常分析访问。前端如何导航到该入口须在原型评审中验证。

## 3. 核心请求与响应约束

| 契约 | 必需信息 | 返回/失败语义 |
| --- | --- | --- |
| 保存简历 | text、expectedRevision、clientEditSequence、幂等键 | revision、acknowledgedEditSequence、savedAt；没有新内容不强制追加相同修订；409不覆盖新稿 |
| 采用建议 | 明确建议与选项范围、各建议版本、基础简历修订、幂等键 | operationId、resultRevision、实际处理状态；同次多项全部提交或全部回滚；部分采用后剩余旧建议暂停 |
| 分析任务 | 用户消息、已保存简历修订、目标版本、有效外发授权 | 202返回taskId/runId；实际失败和等待用户状态通过运行结果返回，不把受理标成完成 |
| 模型候选结果 | action、inputSnapshotId、payload、publicSummary | 服务端以真实身份替代或校验模型回传ID；Schema与来源存在校验不证明语义真实 |
| 搜索结果 | 原查询、供应商、URL、title、获取时间、可用正文/摘要、来源性质 | 可用内容单独作为外部参考，不作为个人经历事实；无结果与失败区分 |

### 纯文本导出

- 已保存稿可通过GET `W/resume/export?revision=...`返回明确修订；前端必须确认页面与该修订一致，不能导出旧稿冒充当前页面。
- 未保存稿优先由浏览器对页面当前文本生成下载/复制，不必向服务器额外发送；文件名或界面标识未保存，不将标识插入正文。失败显示失败且未保存状态不变。
- 导出不是模型任务，不改变事实、当前稿或建议状态。

### 维护备份恢复

采用受控维护命令/脚本而非默认开放HTTP管理端点。命令契约为：进入维护并停止新任务、等待或明确终止运行、生成一致副本及清单、校验、退出维护；恢复在隔离目标执行，演练确认后再切换。具体命令、凭据、数据库版本兼容及文件校验算法在运行手册补齐。无页面入口不等于无需实现或无需演练。

## 4. 数据库约束与迁移要求

| 数据域 | 必填/唯一/关联约束建议 |
| --- | --- |
| 通用 | id、归属、createdAt及生命周期必填；expectedVersion对应服务端rowVersion；不物理级联删除业务历史 |
| 工作区 | profileId必填；CurrentResume.workspaceId唯一；名称非唯一，允许不同人或不同区同名 |
| 材料 | MaterialRevision的(materialId,revisionNo)唯一；byteSize非负；文本粘贴可无原文件键；CONFIRMED时确认文本和时间必填 |
| 引用 | revisionId必须归属同档案materialId；同(workspaceId,materialId)仅一个ACTIVE关系；回收关系不能被当作有效引用 |
| JD/目标 | JD修订不可覆盖；SINGLE_JD恰一份、MULTI_JD至少两份、DIRECTION无JD且方向非空；旧快照保留原选择身份 |
| 简历历史 | (workspaceId,revisionNo)唯一；当前稿内容与对应历史一致；初始化/采用/恢复/替换均保留原因及来源身份 |
| 事实 | FactRevision按(factId,revisionNo)唯一；USER_CONFIRMED须有用户陈述来源；AI候选不作为用户原话 |
| 任务/建议 | task/run/suggestion归属链一致；建议基础修订与输入快照一致；patch、来源、未知等JSON须做结构校验 |
| 幂等 | 操作键在操作者、操作类型及目标作用域内唯一；同键不同载荷拒绝；实际成功结果与业务变更同事务 |
| 回收站 | 本次删除批次和父对象关联必填；首轮expiresAt可空，不以空值误判为立即过期；恢复不复活此前独立删除对象 |
| 稿件来源 | ResumeSourceBinding的(workspaceId,materialId)唯一且同档案；ResumeProvenance按修订追加；独立稿操作清绑定不删历史出处；复制时继承有效当前绑定 |
| 授权与搜索 | 外发授权保存接收方、用途、范围及说明版本；搜索仅存经检查查询和结果，不将原简历混入查询日志 |

外键对不可变历史优先RESTRICT；物理清理由维护流程显式执行，不依赖CASCADE误删共享材料。主查询索引建议覆盖归属/生命周期、工作区修订时间、任务创建时间、运行状态、来源反向依赖及回收批次；索引数量须以真实查询与数据量验证。

迁移顺序建议：档案/材料根 → 不可变材料及事实修订 → 工作区/简历/JD → 引用/目标 → 任务运行/建议/来源 → 操作/回收站/授权 → 索引与约束。根对象currentRevisionId等循环外键在表创建后补加；采用Flyway管理迁移、Spring JDBC访问，不混用自动建表机制。备份前记录schema版本，恢复不直接降级数据库结构。

### 异步运行与轮询字段

- POST任务/回合持久化后返回202，正文包含`taskId`、`runId`、`status`、`statusUrl`和`statusVersion`。重试创建使用幂等键，不能因202或查询断线重复创建任务。
- GET运行返回`status`、`freshness`、`statusVersion`、`startedAt`、`finishedAt`、可空`failureCode`、`nextAction`及结果身份列表；不随每次轮询重复传输全文。列表身份用于按需读取已授权结果。
- 状态为QUEUED/RUNNING时轮询；WAITING_USER/SUCCEEDED/FAILED/CANCELLED/INTERRUPTED停止当前轮询。WAITING_USER提示补充，使用新回合接口创建新run，不修改旧run为运行中。
- 轮询间隔/退避为可配置试验值。页面查询超时显示查询异常，可查询同run重连；401提示重新登录，403处理CSRF/权限，404显示不可用，不把这些结果伪装为模型终态。
- 进程重启将遗留QUEUED/RUNNING标为INTERRUPTED；后台调度失败标FAILED，不自动重发远程调用。取消条件更新返回实际最终状态，不保证供应商请求/计费已撤销。

### 来源独立化请求与冲突

POST `W/resume/independent-copies`请求包含`expectedRevision`、`expectedSourceVersion`及`confirmed: true`，头部携幂等键与CSRF。成功返回`operationId`、`resultRevision`、空的`activeSourceMaterialIds`和保留的`provenance`身份。

操作前自动保存页面编辑；失败或版本变化返回409/实际保存错误，不据旧稿解除绑定。成功事务同时追加新修订与清空当前绑定；即使文本未变化也保留独立化操作原因。辅助引用继续有效，不改变事实状态；有依赖旧简历修订的建议仍按原文版本规则暂停。材料仍被其他工作区绑定时不能借本区独立化绕过其他区检查。
