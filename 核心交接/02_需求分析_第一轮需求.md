# AgentCV 第一轮需求分析

> 状态：用户已接受R11及B01—B03，本轮正式需求修订已确认，范围为R01—R11。已有明确决定继续有效；后续设计如需改变业务规则，应提出变更供用户决定。设计草案须先按本修订重新对齐，不表示已经验收，不启动开发。本次对话最终交付为完整需求文档和设计文档。

## 一句话需求

为已有简历的求职者提供一个可持续使用的简历工作工具：围绕个人档案和独立维护目标简历的工作区，用户可基于 JD 与个人背景发现疑点、补充事实、调整简历；系统清楚展示依据和变化，由用户决定写回、保存和导出。

项目不以“比顶尖模型写得更好”为突破目标。候选价值是把资料、疑点、修改、确认和保存组织在一起，降低反复解释与来回查找成本；收益尚未验证。

## 首轮使用边界（本轮已确认）

- 本人自用与面试演示，由单个操作者使用，可切换不同人的个人档案，不向其他用户开放独立访问。
- 不同个人档案的背景、文件和工作区不能混用；多个档案不代表多个独立访问账号。
- 首轮仅供本人在本机或局域环境使用，不开放公网访问；若通过网络访问，必须有访问保护。

## 导入与导出范围（本轮已确认）

- 第一轮必须支持纯文本、`.docx` 和含文本层的 PDF 导入。
- 首轮处理中文简历和中文辅助材料；支持格式中的中文内容须可读、可检查、可修正并可用于分析。
- 第一轮不支持 `.doc` 和扫描件 PDF，不要求 OCR；遇到不支持的文件须明确提示，并提供文本导入方式。
- 第一轮导出至少支持可复制或下载的中文纯文本；PDF/Word 导出为可选能力，不作为首轮硬性验收项。
- 导入不要求保留原 PDF/Word 视觉排版；提取文本应尽可能保留可理解的段落、标题和内容顺序，解析后由用户检查和修正。
- 第一实现切片先支持文本只代表实施顺序，不缩减第一轮最终格式范围。
- 导入后必须展示可编辑的提取文本；用户检查确认后，内容才允许用于分析。检查确认可与“引用到工作区”合并为一次明确操作。
- 检查确认仅表示提取文本可用，不表示确认材料中经历的真实性，也不自动将其中内容转为用户已确认事实。
- 文件大小/页数限制数值留待设计阶段验证；超限时须提示并拒绝处理。
- 不支持、损坏、无可提取文本或解析失败的文件不得用于分析；须明确说明原因并允许重试或改用文本。
- 部分提取或图文混合的文件，须标出已知异常/可能遗漏；用户可修正提取文本、重试或改用文本，检查确认前不得用于分析。
- 纯文本输入的具体编码兼容范围留待设计验证；不能正确读取时须明确提示，不得静默产生乱码并作为有效内容分析。
- 允许重复导入；检测到同名或相同文件时提示用户，由用户选择保留为两份、查看差异后替换/更新，或取消；不得静默覆盖。

### R03 已确认的导入检查验收条件

| 场景 | 必须满足的行为 |
| --- | --- |
| 成功提取内容 | 展示可编辑的提取文本，供用户检查和修正 |
| 导入中文简历/辅助材料 | 支持格式中的中文内容应正确显示为可检查文本，不要求还原原排版 |
| 尚未确认提取文本 | 不将该导入内容用于分析；仅上传或解析完成不构成检查确认 |
| 用户修正并确认 | 后续分析使用用户确认的文本；是否进入具体工作区仍须满足明确引用规则 |
| 合并检查与引用 | 用户可通过一次明确操作同时确认提取文本并引用到指定工作区 |
| 确认提取文本后 | 不据此自动确认职责、数字或成果等事实，不绕过独立的事实确认规则 |
| 检测到重复文件 | 提示用户选择保留两份、比较后替换/更新或取消；未选择替换/更新前不覆盖已有材料 |
| 不支持、损坏、无文本、解析失败或超限 | 明确提示具体失败类别；不得用于分析，并提供可行的重试、缩小文件或改用文本路径 |
| 部分提取或图文混合 | 显示提取结果和已知异常/可能遗漏；用户修正并检查确认前不得用于分析 |
| 纯文本无法正确读取 | 明确提示编码/读取异常，不把乱码静默当作已确认的有效文本 |

### R03 已确认的材料移除规则

- 用户可从个人档案单独移除一份材料，不要求删除整个档案。
- 若材料已被一个或多个工作区引用，移除前展示关联工作区及影响，并要求用户明确确认；确认后解除相关引用并移除材料，取消时保持不变。
- 确认移除后先进入可恢复回收站；恢复期限及到期清理策略在设计阶段明确。
- 若材料正作为某工作区当前简历，不能直接移除；用户须先为该工作区选择或导入另一份当前简历。
- 移除材料不删除个人档案或相关工作区，也不影响其他档案中的材料。

| 验收场景 | 必须满足的行为 |
| --- | --- |
| 移除未被引用的材料 | 从当前个人档案移除该材料，不影响档案和工作区 |
| 移除已被引用的材料 | 展示所有关联工作区及影响；取消则不变，确认后解除引用并移除 |
| 移除作为当前简历的材料 | 阻止直接移除，要求先为对应工作区更换当前简历 |
| 材料移除后 | 进入回收站，不再作为任何工作区的分析输入；其他档案与工作区不受影响；可在设计确定的期限内恢复 |
| 用户恢复材料 | 按设计确定的回收站规则恢复材料；原工作区引用由用户明确检查/恢复，不因恢复文件而静默进入分析上下文 |

### R03 已确认的材料更新与引用撤销规则（B02）

- 用户可撤销工作区对材料的引用。引用撤销或材料移除后，该材料不再作为该工作区新分析的输入。
- 材料内容更新后，新提取或修正内容仍须按导入检查规则确认；不能凭旧内容的确认直接用于新分析。
- 依赖已撤销/移除材料或旧内容的未采用建议暂停，按有效材料重新处理后才可由用户采用；已保存简历不自动修改。
- 历史AI任务摘要保留原依据身份并标明材料/引用已变化，不因查看摘要重新将失效内容送入分析。

| 验收场景 | 必须满足的行为 |
| --- | --- |
| 用户撤销引用或移除材料 | 后续分析不再使用该引用；依赖它的未采用建议暂停，不能直接写回 |
| 用户更新被引用材料 | 新内容须检查确认；依赖旧内容的未采用建议重新处理后再授权采用 |
| 回看材料变化前的任务 | 可识别原依据及已变化状态；不自动修改已保存简历或恢复失效分析输入 |

## 主要对象

- **个人档案**：对应一个人，保存跨岗位范围复用的个人背景。状态区分简历自述、用户明确确认和待确认，不认证现实真实性。
- **求职工作区**：维护一份可独立持续修改的目标简历，以及相关 JD、引用材料、分析和修改记录。岗位方向是其属性，同方向允许建立多个工作区，例如“后端—高并发侧重”和“后端—AI应用侧重”。
- **档案文件区**：保存此人的简历、项目说明、面试记录等基础材料。
- **工作区引用**：只有用户明确引用的文件才进入该工作区分析上下文。
- **工作区当前简历**：每个工作区有一份当前简历，可渐进修改或导入候选新简历比较；旧稿保留为版本。
- **历史版本**：同一工作区内简历的线性修改历史，用于保留修改前后的内容；用户可查看并恢复历史稿，恢复时作为新的当前稿且保留恢复前稿件。需要并行维护的另一份目标简历通过新工作区承载，不建立复杂版本分支。
- **AI任务摘要**：用户可回看的任务目标、AI关键判断、建议理由及后续处理记录；与工作区中的相关任务、建议和简历版本关联，不是模型隐藏思维过程或完整聊天记录。

## 第一轮主流程

```text
首次使用：建立个人档案 → 建立工作区 → 确定岗位方向 → 导入简历并检查确认
再次使用：打开个人档案 → 继续已有工作区或新建独立目标简历的工作区
新建工作区起点：复制同档案已有工作区当前稿 / 选择已检查确认的档案简历材料 / 导入并检查确认新稿
工作区：选择/导入简历与辅助材料 → 检查提取文本并明确引用 → 提供JD或岗位要求
→ 加入或切换JD时，用户决定另建一份还是继续修改当前这份
→ 明确本次分析使用的单份JD、多份JD或无JD的岗位方向
→ 用户明确发起任务 → 系统按需分析/追问/提出疑点（仅导入或切换目标不启动分析）
→ 展示建议、依据、变化和未知 → 用户采用/拒绝/继续调整
→ 采用后按授权范围写回；仅同步用户明确确认的新事实 → 保存工作区简历
→ 导出或复制结果
再次打开工作区：可查看简历历史与AI任务摘要；查看历史不自动重新分析或写回
```

## 已确认的档案、工作区与简历规则

1. 一个档案对应一个人；不同人的背景与文件不能混用。个人背景跨该人的工作区复用。
2. 一个工作区维护一份可独立持续修改的目标简历；岗位方向是工作区属性，同方向可建立多个工作区。更换目标时可继续当前工作区或建立新工作区，由用户选择。
3. 首次进入顺序是：先建立个人档案和工作区，再确定岗位方向，然后导入并检查确认简历。
4. 档案文件区首轮支持简历、项目说明、面试记录等基础材料；每份文件需明确引用给工作区，未引用内容不进入上下文。
5. 每个工作区维护一份当前简历。用户可渐进修改，也可导入另一份简历作比较。
6. 新简历导入后，用户可选择整份替换或逐项采纳；旧稿保留为版本，不静默覆盖。
7. “整份替换”只表示选择该文档作为当前简历，不代表逐条确认事实。新增或冲突的职责、数字、成果仍待确认；用户明确确认后才同步个人档案。
8. 用户希望并行维护另一份目标简历时新建工作区，可选择同一档案下任一已有工作区的当前简历作为起点；系统复制为新区独立当前简历，用户可继续编辑，不必重新导入；新区修改不能覆盖来源工作区当前简历。
9. 加入或切换 JD 时，由用户决定另建一份还是继续修改当前这份，不自动把不同投递目标的修改累加成一份简历。
10. 继续当前工作区不等于综合全部 JD；一次分析默认明确选择一份 JD，也允许用户明确选择多份 JD 综合分析。未选中的 JD 不参与。
11. 从已有简历另建工作区时，以来源工作区当前简历为起点，列出原区引用的辅助材料供用户选择沿用；原区分析和未采用建议不带入新区，同一档案的已确认背景继续复用。新工作区针对新目标重新分析。

### R02/R04 已确认的新简历导入流程

| 入口 | 流程 |
| --- | --- |
| 首次使用 | 建立个人档案 → 建立工作区并明确方向 → 导入中文简历 → 检查并确认提取文本 → 作为当前简历 |
| 已有档案下新建工作区 | 新建工作区 → 复制同档案已有工作区当前稿、选择档案中已检查确认的简历材料、或导入并检查确认新稿 → 将所得内容作为新区独立当前简历并继续编辑 |
| 在现有工作区导入新简历 | 检查并确认提取文本 → 明确选择更新当前这份、另建一份或仅保存为材料 |

现有工作区中导入新简历的三种去向：

- **更新当前这份**：与当前简历比较，由用户整体替换或逐项采纳；修改前的稿件保留为历史，不静默覆盖。
- **另建一份**：以新导入的简历建立新工作区，不先替换原工作区当前简历；可选择沿用原区辅助材料，原分析和未采用建议不带入，同一档案的已确认背景继续复用。
- **仅保存为材料**：存入当前个人档案文件区，不改变当前简历，不自动用于分析；以后可明确引用或用于建立工作区。

共同规则：检查提取文本、选作当前简历或整份替换均不确认经历真实性；与档案存在冲突的内容不能自动覆盖已确认背景。

| 验收场景 | 必须满足的行为 |
| --- | --- |
| 使用已有稿建立新工作区 | 用户选择来源工作区当前简历后，新区取得独立副本并可继续编辑；修改新区内容不改变来源当前简历 |
| 使用档案文件区简历建立工作区（B01） | 允许选择同档案已检查确认的简历材料，形成新区独立当前稿；不要求先放入其他工作区；不得跨人选取 |
| 使用直接导入的新稿建立工作区 | 新稿经检查确认后成为新区当前简历并可继续编辑，不要求先替换其他工作区的简历 |
| 在原区更新当前稿 | 展示比较结果，按用户选择整体替换或逐项采纳，并保留修改前稿件 |
| 在原区导入后另建一份 | 新稿进入新区，原区当前简历不变；辅助材料由用户选择沿用，分析及未采用建议不带入 |
| 导入后仅保存为材料 | 文件归属当前个人档案，当前简历不变，不因保存或检查确认自动进入分析上下文 |
| 新稿含新增或冲突事实 | 不因上述任一去向自动转为用户已确认事实或覆盖档案背景 |

### R02/R06 已确认的工作区与JD验收条件

| 场景 | 必须满足的行为 |
| --- | --- |
| 同方向需要两份不同侧重点的简历 | 允许建立两个工作区，分别维护各自当前简历 |
| 从已有简历另建一份 | 在同一档案下复制来源工作区当前简历作为新区独立当前稿并继续编辑；辅助材料由用户选择沿用；来源JD、分析和未采用建议默认不带入；修改新稿不覆盖来源当前简历 |
| 新区需要使用来源区JD | 默认重新添加；如需共用，用户须在新区明确引用，不因复制简历自动进入分析上下文 |
| 加入或切换 JD | 由用户决定另建一份还是继续修改当前稿 |
| 单份 JD 分析 | 明确选中的 JD 为本次依据，其他已保存 JD 不静默参与 |
| 多份 JD 综合分析 | 仅使用用户明确选中的 JD，区分来源、共同要求与侧重点差异，由用户决定取舍，不默认合并全部要求 |
| 无 JD 分析 | 按用户明确的岗位方向提供参考分析，不冒充具体公司要求 |

### 已确认的分析目标变化与旧建议处理规则

- 用户明确选择新的 JD 或分析目标后，系统可以提示或建议重新分析，但不得仅因选择目标就自动立即触发分析。
- 所有分析均由用户明确发起；系统可提示或建议分析，但导入材料、选择/切换 JD 或修改背景本身不自动运行分析。
- 旧分析及未采用建议保留查看，并标明原分析目标；目标变化后暂停直接采用。
- 用户若希望继续处理该建议，须按当前目标重新分析并取得新的采用决定；未按新目标重新处理的旧建议不能写回当前简历。
- 线性历史的具体记录时机留待设计明确。

| 验收场景 | 必须满足的行为 |
| --- | --- |
| 用户选择新的 JD/分析目标 | 可提示重新分析；不未经用户请求直接启动完整分析 |
| 用户导入材料、切换 JD 或更新背景但未请求分析 | 系统不自动运行分析 |
| 目标切换后查看旧建议 | 旧建议保留查看，并展示原分析目标及暂停采用状态 |
| 用户尝试采用目标切换前的旧建议 | 不直接写回；要求按当前目标重新处理后再由用户决定 |
| 当前目标下重新分析 | 新结果绑定当前明确选择的目标，用户作出新的采用决定后才可写回 |


## 其他已确认规则

- 同一工作区可保留多份公司 JD；默认明确选择一份分析，也允许用户明确选择多份综合分析，区分共同要求、侧重点差异和来源。
- 没有 JD 时，按用户明确的岗位方向提供参考分析；不得静默混入工作区内未选中的 JD 要求。
- 提供完整 JD 时按该 JD 分析；没有完整 JD 时可按用户明确岗位范围提供参考性能力分析，说明这是模型/联网参考，不冒充具体公司要求，也不做职业探索。
- 后续已确认的联网细化：用户明确请求时查询限定的公开岗位/公司招聘信息，有完整JD时默认不搜索；不发送姓名、联系方式、完整简历或面试记录作为搜索查询，不用网页认证个人经历。展示网址、获取时间及来源性质，失败明确提示。供应商方案和依据见[09_模型与联网选型决策记录.md](09_模型与联网选型决策记录.md)。
- 自然对话可发起新增、删除、改写、面试反馈等任务，不要求先选择固定模式。
- 主动疑点不是错误判决；信息不足时追问，未知可保留。这里的“主动”指用户发起分析后系统主动提出疑点，不表示未经请求自动运行分析。
- 缺口建议简短说明“缺什么、为什么提、下一步怎么补”，不能把缺少材料写成已有经历。
- 用户拒绝不写回；采用后只改选定范围。原文变化时旧建议失效并重新确认。
- 只有用户明确确认的新事实才同步背景；模型推断、措辞润色、简历删除和保存本身都不确认/撤回事实。
- 当前工作稿自动保存；并行维护不同目标简历时使用不同工作区，保留简短修改记录，不做复杂版本树。
- 导出至少支持纯文本；PDF/Word 导出不作为首轮硬性验收项。失败须明确提示并保留工作稿。

### R09/R10 已确认的保存与导出失败验收条件

导出内容来源规则（B03）：当前内容已保存时导出当前稿；有未保存内容时明确状态，允许复制或下载页面当前文本并标为未保存内容，不静默导出旧稿。导出或复制成功不等于工作区保存成功。

| 场景 | 必须满足的行为 |
| --- | --- |
| 当前简历自动保存成功 | 明确呈现已保存状态；重新打开工作区可取得已保存内容 |
| 自动保存失败 | 明确呈现未保存状态；尽可能保留当前页面内容并提供复制或文本导出兜底；不承诺关闭页面后恢复 |
| 未保存时切换个人档案或工作区 | 不静默切换；提示未保存，允许留在当前页面重试，或复制文本后明确选择离开 |
| 纯文本导出成功 | 提供可用的文本结果，不改变已保存工作稿 |
| 当前页面有未保存内容时导出/复制 | 明确标识未保存，提供页面当前文本，不静默输出旧稿；完成后仍保持真实的未保存状态 |
| 导出失败 | 明确提示失败，不显示成功；保留已保存工作稿并提供复制或文本兜底 |
| 恢复历史稿或采用建议时保存失败 | 不显示为已保存；保留页面可见内容并提示用户，写回/恢复与持久化状态需明确区分 |

## R07 已确认的采用授权与受控写回

- 支持页面上的明确“采用”操作，也支持对象和范围明确的自然语言授权，例如“采用第二条”。两种方式执行相同的原文、依据及范围校验。
- “帮我改一下”等生成或调整建议的请求，不等于授权将模型建议写入当前简历。
- 授权对象或范围不明确时先澄清，不猜测用户要采用哪些内容；“可以”等简短回应是否构成授权，取决于上下文能否唯一明确对象和范围。
- 用户拒绝不写回；采用后只改授权范围。原文已变化时旧建议失效并重新确认；依赖被纠正或撤回事实的建议，按R08规则重新处理后再交用户决定。
- 采用措辞不等于确认新增事实，不能绕过独立的事实确认规则。

| 验收场景 | 必须满足的行为 |
| --- | --- |
| 页面明确采用某条建议 | 校验通过后只写回该条授权范围 |
| 三条建议中用户说“采用第二条” | 对象明确且校验通过后只写回第二条，不顺带采用第一、三条 |
| 用户仅说“帮我改一下” | 生成或调整建议，不直接将模型改稿写入当前简历 |
| 多个候选对象下用户只说“可以”且无法唯一确定指向 | 先澄清，不写回 |
| 已明确采用，但原文已变化或所依赖事实已失效 | 不因已有授权跳过校验；按对应规则重新处理并取得用户采用决定 |

## R09 已确认的历史稿查看与恢复规则

- 用户可查看同一工作区内保留的历史简历稿。
- 用户明确恢复某历史稿时，将其内容作为新的当前稿；恢复前的当前稿仍保留为历史，不静默覆盖或丢弃。
- 恢复只影响当前工作区简历，不回退个人档案中的已确认事实，也不重新激活旧分析或未采用建议。

| 验收场景 | 必须满足的行为 |
| --- | --- |
| 查看历史稿 | 可查看历史版本内容，且不改变当前稿 |
| 恢复指定历史稿 | 指定内容成为新的当前稿，并保留恢复前的稿件 |
| 恢复历史稿后 | 个人背景确认状态不回退，旧分析及未采用建议不因此恢复为可采用状态 |

## R01 已确认的个人档案删除要求

- 用户可删除个人档案。
- 删除前展示将受影响的档案数据范围，并要求用户明确确认；未确认或取消时不删除。
- 确认后将该档案及其所属数据移入可恢复回收站，不影响其他个人档案；恢复期限及到期清理方式在设计阶段明确。

| 验收场景 | 必须满足的行为 |
| --- | --- |
| 用户发起删除 | 展示受影响的数据范围并要求明确确认 |
| 用户取消或未确认 | 档案及所属数据保持不变 |
| 用户明确确认 | 档案及所属数据进入可恢复回收站，不影响其他档案 |
| 用户恢复档案 | 按设计确定的回收站规则恢复档案及其所属数据，不影响其他档案 |

## R02 已确认的工作区删除要求

- 用户可单独删除某个工作区，不要求删除所属个人档案。
- 删除前展示该工作区将受影响的数据范围，并要求用户明确确认；未确认或取消时不删除。
- 确认后将该工作区及其所属数据移入可恢复回收站，不影响个人档案本身及其其他工作区；恢复期限及到期清理方式在设计阶段明确。

| 验收场景 | 必须满足的行为 |
| --- | --- |
| 用户发起删除工作区 | 展示该区简历、JD、引用材料、历史稿和分析等受影响范围并要求明确确认 |
| 用户取消或未确认 | 工作区及所属数据保持不变 |
| 用户明确确认 | 工作区及所属数据进入可恢复回收站，保留个人档案及其他工作区 |
| 用户恢复工作区 | 按设计确定的回收站规则恢复工作区及所属数据，不影响同档案其他工作区 |

## R08 已确认的事实确认与同步规则

- 用户在自然对话中清楚陈述自己的事实，可以作为明确确认，不要求每次额外点击确认清单。
- 系统须展示本次同步了哪些事实，允许用户查看并纠正或撤回记录；记录内容不得超出用户实际陈述的范围。
- 含糊表达、假设、拟议措辞及与已有背景冲突的内容须先追问澄清，不能直接记录为已确认事实或静默覆盖原记录。
- 采用简历措辞、检查提取文本、整份替换、保存简历均不能替代事实确认。材料中的自述也不能仅因导入而成为用户已确认事实。

| 验收场景 | 必须满足的行为 |
| --- | --- |
| 用户说“我负责接口设计，没有负责部署” | 可记录其明确陈述，并展示同步结果；不得加强成独立负责或额外增加部署职责 |
| 用户说“能不能写成我负责部署” | 视为拟议措辞或修改请求，不能直接记为已确认经历；需要澄清事实 |
| 用户表达含糊或与已有背景冲突 | 先追问，不静默升级为已确认事实或覆盖已有记录 |
| 用户发现同步记录有误 | 能查看并纠正或撤回已记录事实；不能只能通过删除简历句子处理 |
| 用户只采用建议或保存简历 | 不因此自动确认建议中的新增事实 |

### 已确认的事实纠正与撤回影响

- 纠正或撤回背景事实不自动修改任何工作区已保存的简历；对已识别的相关内容提示核查，由用户决定是否修改，仍须遵守选定范围和采用规则。
- 依赖旧事实的待采用建议暂停直接采用，须按新背景重新处理后，再由用户决定是否采用。
- 撤回仅表示该内容不再作为用户已确认的依据，不等于判定旧说法为假。
- 对关联内容的提示以系统已识别的关系为范围，不承诺发现所有语义关联；如何识别和维护依赖关系在设计阶段明确。

| 验收场景 | 必须满足的行为 |
| --- | --- |
| 用户把“负责部署”纠正为“协助部署” | 更新背景记录并展示结果，不自动改写各工作区已保存简历；对已识别的相关内容提示核查 |
| 未采用建议仍依赖旧的“负责部署”事实 | 暂停直接采用，按新背景重新处理后再交用户决定 |
| 用户撤回一条已确认事实 | 不再以其作为已确认依据，不把撤回解释成该事实已被判假 |
| 相关内容需要纠正 | 提示或重新生成建议不能自行写回简历，须经用户选择采用 |

## R11 已确认的AI任务摘要回看

- 用户可在工作区回看已保存的AI任务摘要，重新打开工作区后仍可查看，不要求检索完整聊天历史。
- 摘要简短说明本次用户目标、所针对的简历和JD/方向、实际使用的材料、AI主要判断或建议、简要依据及未知/待补充项。没有使用的材料不得被写成依据。
- 关联显示用户采用、拒绝或尚未处理的状态；涉及写回时，区分采用意图、写回结果和保存结果，并关联对应简历版本。仅分析或追问未改稿时也能留有摘要。
- 摘要陈述对用户公开的判断与理由，不要求保存或展示隐藏思维链、完整模型请求、提示词版本、Token日志或开发过程审计记录。
- 回看历史摘要不表示旧判断仍适用，也不允许绕过目标、原文和事实依赖变化后的建议失效规则。
- 摘要记录失败须提示未保存，不伪装为历史已记录；摘要不能反向替代原材料或将AI推测升级为确认事实。

| 验收场景 | 必须满足的行为 |
| --- | --- |
| AI分析或追问后没有修改简历 | 可保存简短任务摘要，不以发生简历修改为记录前提 |
| 重新打开工作区 | 可回看已保存任务的目标、主要判断/建议、简要依据和未知项 |
| 用户采用或拒绝某建议 | 在关联记录中可看到对应处理状态；只有实际写回成功才标为已写回 |
| 切换JD、修改原文或纠正背景后回看旧任务 | 可见原任务目标与历史属性；相关旧建议仍按失效/暂停规则处理 |
| 保存摘要失败 | 明确提示未保存，不显示为已持久化的历史记录，不改变已保存简历 |
| AI解释缺乏依据 | 保留为未知或待补充，不将摘要说明当作事实认证 |

## 不作为首轮目标

- 不做职业探索、自动决定用户职业或自动替用户认证经历。
- 不保证主动发现所有问题，不保证录用。
- 不做完整聊天历史检索、复杂版本树、多用户协作/客户管理；此排除不影响R11要求的简短AI任务摘要回看。
- 不要求导入时完美还原 PDF/Word 排版；不要求 .doc、扫描件 PDF/OCR 或 PDF/Word 导出。
- 不预设复杂多 Agent/自主 Agent 架构。

## 首轮行为验收

基础流程用一个个人档案、一个工作区、一份真实简历和一份 JD 跑通：导入检查、引用材料、提出疑点/缺口、用户补充、局部对照、采用/拒绝、保存再打开、导出失败文本兜底。未知、冲突和未采用建议不能变成已确认事实。

补充工作区/JD场景：同方向从已有简历另建工作区并独立修改；在原工作区继续使用另一份 JD 迭代；明确选择多份 JD 综合分析并区分来源和侧重点。基础流程不替代全部首轮需求的逐项验收。

逐项验收 R01—R11 及本文确认的异常路径，重点验证档案/工作区隔离、既有简历复制后独立编辑、中文材料引用和解析状态、建议依据与未知展示、用户授权后受控写回、事实确认状态、AI任务摘要重新打开后可回看，以及保存/导出/删除失败处理。

首轮验收是产品行为验收，不是模型效果或用户价值提升证明。不承诺疑点检出率、模型准确率、效率提升或优于普通模型；效果相关数据后续按真实任务实测并单独报告。
