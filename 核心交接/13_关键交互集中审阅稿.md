# AgentCV 关键交互集中审阅稿

> 状态：用户已确认采用本交互结构。使用虚构固定示例，不运行模型、不实现页面，不作为效率或效果证据。视觉细节、响应式布局和可点击原型仍待后续验证。

## 1. 评审范围与页面结构

优先桌面浏览器自用与演示。本稿评审操作路径、信息层级和反馈；不确认配色、像素尺寸或移动端布局。

```text
┌ 当前档案：示例求职者 | 当前工作区：后端—A公司 | 当前稿 v3 已保存 ┐
│ 工作区导航      │ 当前简历（编辑区）          │ 任务与建议       │
│ 后端—A公司      │ 标题、段落与原文           │ 当前任务目标     │
│ 后端—B公司      │ 被选中修改范围高亮         │ 对话 / 追问      │
│ +另建一份       │                           │ 建议对照卡       │
│                │                           │ 输入自然任务     │
├ 档案材料 / 背景 │ 历史稿 | 复制 | 下载文本    │ AI任务记录       ┤
└──────────────────────────────────────────────────────────────┘
```

- 左侧只做档案/工作区导航；材料、背景及回收站按需进入抽屉/独立管理视图，不长期占满阅读区。
- 顶部工作区上下文显示本次JD/方向与引用材料摘要，可展开修改。区分“保存在档案中”和“本次可用于分析”。
- 中间当前稿是唯一正式工作文本；右侧模型输出是候选，未采用不会出现在当前稿中。
- 对话里点击建议，在侧边展开详细对照，并定位中间原文；不要求用户在长回答中自行寻找改动。

## 2. 首次进入和导入

1. 口令登录 → 创建/选择个人档案 → 新建工作区，填写名称及岗位方向。
2. 选择起始简历：上传/粘贴新稿、选本档案已检查确认的材料、复制本档案已有工作区当前稿。无可选来源时对应项不可用并说明原因。
3. 上传后显示原文件名、类型和提取状态；提取完成进入检查视图，保留原件查看/下载入口，展示可编辑文本及已知异常。不能显示“识别完全正确”之类保证。
4. 提供“确认文本并作为当前简历”，提示“确认提取内容可用，不代表确认全部经历真实”；不要求逐句勾选。
5. 辅助材料可单独检查并“确认并引用到本工作区”；取消检查可以离开，但材料仍待检查，不用于分析。

不支持、解析失败或超限：原地说明原因，提供重试/粘贴文本，不跳成空白成功页。重复文件提示保留两份、比较更新或取消，不默认覆盖。

## 3. 主任务：按JD调整项目描述

### 3.1 选择目标与发起

用户在顶部选择“本次使用：A公司JD”，可切换为多JD综合或无JD方向参考；未选中JD不参与。选择本身不调用模型。

用户输入：“按这份JD修改项目描述，职责不清先问我。”

状态依次显示：正在保存当前稿 → 已保存 → 正在分析。保存失败则停在“未保存，尚未开始分析”，提供重试与复制/下载当前文本。

首次外发前说明接收方MiMo和本次资料范围，明确授权；范围/供应商变化按授权规则处理。完整JD默认不搜索；“查公开岗位资料”须用户明确触发，并提示搜索不发送完整简历。

后台运行时只展示真实状态，不伪造百分比或阶段进度；可取消。页面查询失败说明“状态查询失败，可重连查询”，不显示模型任务已经失败，不重复提交。

### 3.2 追问与事实反馈

原文（固定示例）：“参与接口设计与部署工作。”

AI：“接口设计和部署分别承担了什么职责？”

用户：“我负责接口设计，部署只是协助。”

显示轻量记录反馈：“已记录：负责接口设计；部署为协助。［查看/纠正背景］”。这不表示当前简历已改；不再要求对清楚陈述重复点击确认事实。

用户可回答“不知道”或暂不处理，未知保留。发送针对追问的补充表示继续本任务，无需再输入一遍初始目标；可以明确选择暂不继续。

### 3.3 对照与采用

建议卡示例：

```text
建议1 · 项目经历第2段 · 待处理
原文：参与接口设计与部署工作。
你的补充：负责接口设计；部署只是协助。
建议：负责接口设计，协助部署相关工作。
变化：明确两项工作的职责边界。
依据：本轮用户补充（可展开原始陈述）；当前稿v3。
未知：实际范围和成果指标尚未补充，本条不新增这些内容。
[采用此项] [不采用] [继续调整]
```

原文、建议、变化默认可见；补充、依据与未知保留明显入口，不能只靠颜色区分确认状态。点击来源可查看本次实际使用片段及来源状态，不保证所有语义风险被识别。

- 点击“采用此项”或明确说“采用第1条”：同等校验，不强制重复确认；成功后当前稿高亮变更，显示“已采用并保存为v4”，建议保留已处理状态。
- 多项可勾选后“采用所选”；一次原子完成。部分采用后其他基于旧稿的建议显示“当前稿已变，需重新处理”，不能直接继续采用。
- “继续调整”仍生成候选，不直接改当前稿；拒绝不改稿。
- 原文、目标或依赖已变化，禁用直接采用并说明具体原因，提供用户发起重新处理的入口，不自动收费重分析。
- 写回/保存失败不得显示成功；已保存稿不变，候选内容仍可查看/复制；若页面有未保存手工编辑，保留并标明，不让候选悄悄覆盖。

## 4. 保存、导出、历史回看

- 当前稿状态始终显示：未保存、保存中、已保存或冲突；下载成功不更新保存状态。
- “复制/下载文本”已保存时取当前稿，未保存时明确取页面当前文本；提示不插入简历正文。
- “简历历史”按关键操作组织，选旧稿可查看，明确恢复后形成新当前修订；不回退个人事实、不激活旧建议。
- “AI任务记录”按任务展示时间、目标、判断摘要、依据/未知、采用/拒绝及写回保存结果；无改稿的追问也能回看。旧任务显示历史目标及依据变化，不默认展开完整聊天。
- 摘要保存失败单独提示“任务记录未保存，可重试”，不能把已保存稿显示成失败；重试记录不重复写回。

## 5. 工作区切换与来源管理

- 切JD时提供“继续改当前这份 / 另建一份”，不默认新建；继续时旧建议暂停，另建走三种简历来源初始化。来源JD不自动带入。
- 同方向工作区并列显示名称和目标摘要；复制后文本独立，当前材料绑定按已确认规则继承。
- 移除当前来源材料时列出相关工作区，提供“先更换当前简历”及“将已保存文本转为独立稿”的入口；后者明确解除当前绑定但保留历史出处，不等于撤销辅助引用或事实。
- 删除预览展示对象与影响，确认后进入回收站；不将共享档案材料随工作区误删。回收站首轮不自动永久清理。
- 有未保存内容时切档案/区，先尝试保存；失败不静默切走，允许重试或复制文本后明确离开。

## 6. 已确认的交互结构与待验证细节

用户已确认本稿交互结构：简历居中、右侧任务/建议、左侧导航；材料/背景按需展开；原文/建议/变化默认可见，依据/补充/未知可展开；补充后继续任务；历史稿与AI任务记录分开；保存、写回、摘要和导出失败分别显示真实状态。
