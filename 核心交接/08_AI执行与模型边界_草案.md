# AgentCV AI执行与模型边界（详细设计草案）

> 整体方向已确认：受约束的灵活编排，不固定评分→改写→审查流水线，不预设多Agent。供应商与限定联网方案A已确认。本文动作协议、具体调用预算/重试及上下文处理仍为待评审设计建议，未接入模型测试。LangChain4j为优先接入方向，不据框架能力推导业务可靠性。

## 1. 分工与调用结构

```text
用户任务 / 用户补充 / 明确采用授权
    → 应用路由：核对身份、任务与操作类别
    → 需分析当前稿时自动保存 → 保存成功才构造输入快照
    → 模型返回结构化候选动作
    → 程序校验动作、来源、参数、预算和快照状态
       ├─ 读取本次授权材料片段 → 有界继续模型调用
       ├─ 追问 → 展示问题，停止运行并等待用户
       ├─ 提出建议 / 分析结论 → 保存候选结果与简短任务摘要
       └─ 无法处理 / 失败 / 过期 → 明确提示，停止
用户采用建议 → 独立写回服务校验 → 事务提交 → 实际结果关联任务记录
```

候选起步方案是一个面向任务的模型服务，可多次调用同一模型完成必要步骤；应用编排器管理任务状态。接口分离不等于建立多个独立Agent。纯查看、复制/导出、页面保存、历史恢复等明确程序动作不需要为了“Agent化”额外调用模型。

自然语言输入可让模型识别任务和授权候选，但模型不能直接执行保存/删除/事实同步。程序以用户实际表达、明确目标、生命周期及版本进行控制。有歧义先追问，不能将模型高置信度当成用户授权。

## 2. 候选动作白名单

| 动作 | 允许输入与结果 | 程序控制 |
| --- | --- | --- |
| READ_CONTEXT | 读取本次上下文清单中的材料ID、修订、段落/页范围 | 只读；核对档案、引用有效性及本次输入白名单；不接受本地路径或任意对象ID |
| ASK_USER | 简短问题、提问原因、关联未知/冲突项 | 正常等待状态，不当失败；必须停止当前执行，不模拟用户回答 |
| REPORT_ANALYSIS | 岗位要求、疑点/缺口、简要依据和未知 | 疑点不是错误判决；区分JD原文与方向参考；不改稿 |
| PROPOSE_CHANGE | 基础简历修订、目标范围、原文、候选替换、来源与未知 | 保存为建议；程序比较原文和范围，生成变化展示；不得直接写回 |
| CLASSIFY_USER_STATEMENT | 指向用户原始消息的清楚陈述、假设、含糊或冲突候选 | 事实服务检查原始表达；冲突先澄清，不凭改稿结果确认事实 |
| RESOLVE_USER_ACTION | 明确采用/拒绝的建议ID和范围候选 | 仅解析意图；应用执行07中的授权和事务检查；歧义不执行 |
| FINISH / CANNOT_PROCEED | 面向用户的结论摘要或不能继续的原因 | 结束本次运行，保留未知；不能自动扩大材料范围或发起其他任务 |

不提供：任意SQL、文件系统路径访问、Shell、全档案自由搜索、跨档案读取、自动写回、自动确认事实、删除/恢复工具。删除/恢复可以通过自然语言进入程序的影响预览与确认流程，但不是模型循环中可直接执行的工具。

## 3. 模型输入与输出契约

### 3.1 输入分层

1. 程序规则：任务范围、动作白名单、不可越过的用户授权与事实边界。
2. 当前用户请求：原消息及与本任务直接相关的补充；不能将AI代答作为用户事实。
3. 输入快照：当前档案/工作区身份、已保存简历修订、分析目标与明确选择的JD修订、有效材料引用及确认状态、相关事实和状态。
4. 已产生结果：本任务必要的待处理建议或工具结果，明确标为模型输出而非事实来源。

材料、JD、简历中的文本都是不可信数据，不是可覆盖程序规则的指令。历史任务摘要仅帮助用户回看；不能作为新增事实依据，也不能因摘要提到材料就恢复其引用。

### 3.2 结构化响应

建议统一返回：`action`、`taskId`、`inputSnapshotId`、`payload`、`publicSummary`；具体JSON Schema在接口设计定稿。

- action必须属于允许集合；程序记录实际task/run身份，模型回传值必须匹配，不能据其改换对象。
- READ_CONTEXT必须包含白名单内的sourceId/sourceRevision和读取范围。
- ASK_USER包含问题及关联缺口，不得在同一响应中伪造已得到回答。
- PROPOSE_CHANGE包含建议项ID、baseResumeRevision、目标片段、originalText、replacementText、sourceRefs、briefReason及unknowns。删除或新增也应有明确锚点和空文本语义，不能用模糊“优化项目二”充当写回位置。
- REPORT_ANALYSIS包含要点、来源身份和简要理由；多JD区分共同与差异，无JD不冒充公司要求。
- publicSummary只保留公开结论与理由，不要求模型隐藏思维链。用户处理状态和写回成功必须由程序补充，不让模型生成这些事实。

程序校验顺序：结构/动作 → 对象归属 → 输入快照 → 来源存在及被实际读取 → 目标范围与原文 → 业务状态。非法来源、跨人对象、过期原文、不完整建议不得进入可采用状态。

来源身份和字符串匹配只能校验“引用可定位”，不能证明职责、数字或因果解释语义正确；未知仍须展示，用户仍负责判断。不得把来源校验通过标成经历真实性认证。

## 4. 事实同步与采用授权

- 清楚自然语言陈述可作为明确确认，不增设每次单独点击事实清单的硬性步骤；保存后展示具体记录，允许纠正/撤回。
- 事实服务必须保留用户原始消息及对应片段，将模型抽取视为候选。不能用关键词或一个置信分数声称可靠识别全部否定、假设和职责边界。
- “我做接口设计，没有部署”不能被抽取成“负责部署”；“能否写成我负责部署”不能成为已确认事实。含糊或冲突交回用户。
- “采用第二条”应解析到当前展示、唯一确定的建议与范围；明确时不强制重复点击确认，但仍执行全部版本/依据检查。
- 已采用措辞、导入检查、保存、恢复与模型自检都不触发事实确认。

事实理解和自然语言指代仍存在模型错误风险；需要用否定、转述、假设、冲突、过期建议等用例验证。模型自检不是认证层，不能用第二个模型替代程序授权边界或用户事实确认。

## 5. 预算、重试与停止条件（建议，尚待确认）

### 已确认的参数校准安排

用户确认不凭经验预先固定预算数字；第一版实现完成后，由项目负责人用自测校准，不以外部用户或上线为前提。当前设计阶段说明可配置限制、观测项和测试场景，不声称参数已通过验证。具体执行协议仍按本文评审状态管理，不能将校准安排当成所有细节已批准。

- 第一版交付前必须有有限的试验配置，不能以“待测试”为由不设上限；初始值在开发接入所选供应商时说明依据并记录为试验值。
- 可配置项包括调用次数、单次/整轮超时、读取次数与内容量、输出上限、重试/结构修复次数；数值及计量单位待供应商协议确定。
- 首版需具备最小测试观测：task/run身份、配置快照、调用/读取次数、耗时、供应商实际提供的Token统计、重试原因、停止原因、运行及写回/保存结果。未提供的指标记未知，不估造。
- 测试包括正常任务、长材料/多JD/信息冲突等边界任务，以及超时、限流、错误JSON、重复请求和运行中输入变化等故障场景。
- 调整配置时记录测试输入版本、预期、实际、失败类别、调整理由及复测结果。重点检查正常任务被过早截断、无效循环/等待和重复写回，不把自测结论外推为用户收益。
- 这些是内部测试所需的最小运行记录，不将R11用户摘要扩成完整提示词、隐藏思维链或敏感正文日志。
- “第一版后校准”不等于延后所有测试：开发中仍需单元/集成测试；第一版可运行后再集中开展端到端参数校准。本轮不执行代码或模型测试。

- 一次用户发起的运行必须具有模型调用次数、总耗时、输出长度和工具读取预算；具体数值在供应商能力明确后确定，不做无限Agent循环。
- 提出追问、形成可供用户选择的建议、完成结论、无法继续、预算耗尽、用户取消均为停止点；补充后继续属于用户触发的新回合。
- 格式错误可评估一次受限修复调用；只能修复结构，不能借机扩大授权、编事实或读取更多资料。修复失败明确停止，不返回貌似可采用的残缺建议。
- 超时或可重试网络错误只在总预算内有限重试；模型分析重试不执行变更工具。非幂等业务变更重试必须使用Operation结果检查，不由模型重新发起。
- 已发起模型请求未必可立即停止远端计费；用户取消后应用不再接受迟到结果为当前可采用建议，界面不承诺已撤销供应商请求。
- 输入在运行期间变化：结果保留为历史并标过期，停止采用；不能以“模型已分析完成”为由忽略新状态。

## 6. 上下文容量与联网边界

- 大材料先提供授权来源清单，再按当前任务读取必要片段；本轮不因“简历助手”自动引入向量数据库。
- 容量不足时应说明未纳入/未读取的范围并让用户缩小任务，不能静默截断后声称完成全量分析。
- 允许程序选择与任务相关的已确认背景，但不能把未引用的档案文件内容伪装成背景事实。实际发送给供应商的资料范围应可说明。
- 已确认方案A：MiMo `mimo-v2.6-flash`主选，DeepSeek `deepseek-flash`手动备选；不自动切换生成供应商。用户显式请求后由程序调用DeepSeek Search查询限定公开岗位/公司招聘资料，必要时评估Fetch；不提供模型自由搜索工具。
- 搜索不发送姓名、联系方式、完整简历或面试记录，不认证个人经历；展示来源网址、获取时间和性质，失败明确提示，不伪造公司要求。生成API发送资料与搜索查询分开控制。供应商条款、接口和真实效果未验证，依据及面试边界见[09_模型与联网选型决策记录.md](09_模型与联网选型决策记录.md)。

## 7. 一个完整任务示例

用户：“根据这份JD调整项目描述，职责不清先问我。”

1. 程序自动保存当前稿，绑定简历r12、目标t3、JD j2/r1及已引用材料；失败则不分析旧稿。
2. 模型读取授权项目片段，发现职责不清，返回ASK_USER：“你负责接口设计还是也负责部署？”此处停止，记录简短任务摘要。
3. 用户：“我做接口设计，部署只是协助。”事实服务记录其明确陈述并展示，不加强成独立完成。
4. 用户继续任务，程序基于更新背景捕获快照；模型提出带定位、依据和未知的候选改写，不直接落稿。
5. 用户：“采用第二条。”应用定位唯一对象，核对版本、来源与授权；事务写回新稿r13、历史及真实操作结果。
6. 摘要保存失败时明确记录未保存，但r13仍是已保存稿；只补记摘要，不重复采用。
