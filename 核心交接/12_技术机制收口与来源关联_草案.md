## 1. 数据访问、迁移与认证推荐

| 决策 | 推荐与理由 | 对照方案与代价 |
| --- | --- | --- |
| PostgreSQL访问 | Spring JDBC的JdbcClient/JdbcTemplate，按业务Repository组织显式参数化SQL，事务在应用服务边界管理 | JPA可减少常规映射代码，但本项目版本条件更新、不可变修订和回收关联较多；MyBatis同样可行但新增映射框架。选择显式SQL为便于掌握查询与并发，不声称更高性能 |
| 结构迁移 | Flyway管理版本化迁移，包含PostgreSQL所需模块；不用ORM自动更新结构或另一套初始化脚本同时管理同一结构 | 需要手写迁移和恢复前结构版本检查，换取可追溯变更 |
| 认证 | Spring Security、单操作者口令、服务端会话、CSRF；不引入JWT或用户注册平台 | 重启后会话可失效并重新登录；不为了单实例引入Redis会话 |
| CSRF交互 | GET `/api/v1/csrf`在未登录时获取token及headerName；登录/退出后重新获取；写请求和上传均在头部携带token | 需验证所选Security版本的延迟token和会话配置，不照搬其他大版本配置。token响应不缓存，不放URL日志 |

SQL必须参数化；排序字段采用服务端白名单，不能直接拼接用户输入。跨对象归属与版本条件同时进入查询/事务校验；引入JDBC不自动解决授权或竞态。

官方参考：
- [Spring JDBC](https://docs.spring.io/spring-framework/reference/data-access/jdbc/core.html)：JdbcClient/JdbcTemplate与参数化操作能力；本次返回Framework 7文档，仅作机制参考，Boot 3.5应复核其管理的Framework 6.2对应API，不混用大版本。
- [Boot 3.5数据库初始化](https://docs.spring.io/spring-boot/3.5/how-to/data-initialization.html)：Flyway集成、数据库模块和初始化方式的边界，具体依赖树仍待验证。
- [Security CSRF](https://docs.spring.io/spring-security/reference/servlet/exploits/csrf.html)：SPA token处理及认证/退出后的更新；本次为当前7.x页面，最终配置须核对Boot 3.5管理的6.x版本。

## 2. 异步执行与状态更新推荐

- 前端提交任务后，服务端先持久化运行记录，返回202与taskId/runId。调用模型在有界线程池执行，不占据数据库事务等待远端。
- 首轮使用状态轮询，不默认SSE/WebSocket或Token流式输出。轮询只查询状态，不重复发起模型请求；间隔、退避和超时作为可配置试验参数。
- 运行状态补全为QUEUED、RUNNING、WAITING_USER、SUCCEEDED、FAILED、CANCELLED、INTERRUPTED；输入新鲜度CURRENT/STALE独立表示。WAITING_USER已停止调用，用户补充后创建同任务新run。
- 页面离开不等于取消；重新打开可查询已有run和任务摘要。网络查询失败显示连接/查询异常，不把未知终态猜成任务失败或重新收费执行。
- 进程内线程池不是可靠队列；数据库记录是查询依据。提交持久化成功但调度失败须标失败；重启时将遗留QUEUED/RUNNING标为INTERRUPTED，不自动恢复计费调用或重放写回。后续由用户明确重试。
- 取消与结果提交使用状态条件更新竞争；取消先提交时迟到结果不可成为当前可采用建议；结果先完成则取消返回实际终态，不假报已取消远端调用。
- 模型候选结果、建议及run成功状态建议同事务提交；文字摘要可独立补记，失败不伪装建议未产生或简历未保存。
- 写回仍是单独用户授权命令，不在后台分析任务成功后自动执行。

主要取舍：轮询更容易重连、调试和演示，代价是进度更新不如推送及时且产生查询请求。首轮没有逐Token展示硬需求，因此不先承担推送重连与流式半成品处理成本。若后续需要流式体验，另外评审，不改变受控写回。

## 3. 简历来源：历史出处与当前绑定分开

已确认采用两种不同关联，避免把“引用”和“简历当前内容”混为一体：

- `provenance`：不可变历史出处，记录初始化/替换/恢复时来自哪一区哪个修订、哪份材料哪个修订；用于回看，不等于新分析自动获得源文件权限。
- `activeSourceMaterialIds`：当前稿仍选作来源的材料集合，用于已有需求“材料作当前简历时先更换再移除”的检查。与辅助材料的显式引用分开管理。

| 操作 | 建议关联规则 |
| --- | --- |
| 从材料初始化或整份替换 | 独立保存确认文本，provenance记录材料修订，当前来源绑定到该材料 |
| 从已有工作区当前稿复制 | 保存来源区/修订出处，复制其当前来源材料绑定；复制前检查同档案与材料有效性。原区删改不改变新区文本，材料移除预览需列出所有仍绑定区 |
| 普通编辑或采用AI改写 | 不自动解除当前来源绑定；已保存文本不因材料更新自动变化；引用/建议状态按既有规则处理 |
| 新稿逐项采纳 | 保留旧出处并记录本次候选材料修订；将实际采纳内容的候选材料加入当前来源集合。不把该材料自动当作辅助引用 |
| 更换当前简历 | 新稿独立保存后原子更新来源集合；从已保存文本创建明确的独立文本稿也可作为更换方式，保留旧出处与历史，不必强迫重传相同文件 |
| 历史恢复 | 用历史文本生成新修订，保留历史出处。只有仍有效的来源材料可重新绑定；材料已回收/清理时提示不可用，文本仍可恢复，不自动复活材料、引用或建议 |

“从当前文本建立独立稿并解除材料绑定”已确认为明确操作，不因日常编辑静默解除。解除来源绑定不撤销辅助引用；若同材料仍被明确引用，移除时仍按引用影响确认处理。它也不撤回个人档案事实。

这组规则解决两个风险：历史出处不因编辑而丢失；源文件也不会因历史快照一直存在就永远无法清理。后续来源不存在时显示不可用，不承诺原件始终能打开。

## 4. 版本锁定与验证的边界

- Java 17、Boot 3.5方向已定；JDBC、Security、驱动和Flyway优先采用选定Boot补丁的依赖管理，不独立拼装其最新大版本。
- PostgreSQL服务器与pg_dump/pg_restore需确定兼容组合；Node/Vite/Vue/TypeScript及POI/PDFBox/LangChain4j需写出精确版本清单并锁定，不使用浮动latest。
- [Vite当前指南](https://vite.dev/guide/)本次显示v8.3.4与Node 20.19+/22.12+要求，并提醒模板可能要求更高；这不证明本机已有对应版本，也不代表必须选当前最新版本。
- 当前未做本机工具链核查、依赖解析、构建或解析样本测试，因此精确版本不能标为已验证。设计交付须有版本候选与验证门禁；真实兼容结论在获准开展最小接入验证时记录，不等于先开发完整功能。

## 5. 补充验收设计（未执行）

| 场景 | 预期 |
| --- | --- |
| 请求已受理但进程重启 | run为中断可回看，不自动再调用模型或再次写回 |
| 用户补充追问 | 关联同一task新run，旧run不从等待状态偷偷继续 |
| 查询状态断线再连接 | 查询原run而非重复创建，不能将查询失败当成模型失败 |
| 登录或退出后token变化 | 前端刷新CSRF信息，缺失/过期token写操作拒绝，凭据不出日志 |
| 多工作区源自同一材料 | 移除预览显示所有当前绑定；原区删除不改变新区文本 |
| 独立文本稿替换后移除原材料 | 已解除来源绑定的工作区不再被错误阻止；辅助引用仍需处理 |
| 恢复来源材料已清理的历史稿 | 文本可恢复，原来源显示不可用，不重建文件或有效引用 |
