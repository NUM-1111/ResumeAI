## 6. 进入开发的门槛

用户审阅清单后基本认可，并提出环境/依赖兼容验证作为开发阶段首环节。采用以下分阶段门禁，不再要求开工前完成所有运行验证；这不表示完整OpenAPI、DDL或运行手册已经补齐，也不将预计兼容视为验证通过。

1. 开发起步：按已确认业务/架构基线进行环境核查、精确版本选择和最小启动/构建验证，记录命令、实际结果和锁定版本；失败先修复该环节，不生成整套功能赌兼容。
2. 对应切片实现前：补齐该切片涉及的请求/响应字段、数据约束、迁移及验收预期。完整接口和DDL可随切片细化，不让代码独自决定未说明的业务行为。
3. 对应能力交付前：通过登录/保存/隔离等确定性测试；备份恢复功能需有实际命令及演练，原型可随第一版界面迭代验证，不单独阻塞全部开发。
4. 首版可运行后：执行端到端、模型对照、故障注入及预算/超时/成本校准；真实材料外发前必须先核查供应商API条款与授权。
5. 进入实现时明确新WSL仓库位置、第一切片边界和验收记录；不得改动旧原型。环境问题通常先调整版本/配置，若必须改变技术方向、业务范围或数据边界，仍须提出变更，不保证绝不回退。

## 7. 开发切片与首轮范围

建议的第一个垂直切片：

1. WSL工程骨架与最小运行说明。
2. 本机单操作者访问保护及配置占位（密钥不入库），完成会话/CSRF安全测试。
3. PostgreSQL迁移骨架、单档案创建/切换、工作区创建与方向设置。
4. 中文纯文本导入、检查确认、建立当前稿、自动保存、重新打开及失败状态。
5. 第一切片通过后再加DOCX/PDF材料解析和引用；后续依序加入AI任务摘要/追问/建议、写回、历史恢复、删除回收站、联网限定搜索、文本导出及备份恢复。

此顺序只是分阶段实施，不代表首轮最终发布可缺少必需能力。首轮发布前仍须实现R01—R11；中文`.docx`与文本层PDF导入、备份恢复实现和演练、外发授权、任务摘要回看等均在首轮发布门槛内。若开发时间不够，应减少切片范围或调整发布日期，不得将阶段性文本切片描述为完整首轮交付。

## 8. 精确版本锁定门禁

| 组件 | 当前方向 | 锁定前必须取得的证据 |
| --- | --- | --- |
| JDK / Boot | Java 17 / Spring Boot 3.5 | Boot补丁版官方要求、安全/支持信息、WSL构建启动、BOM冲突检查 |
| Node / 前端 | Vue 3 + TypeScript + Vite | 选定Node LTS、Vite最低Node要求、构建和Boot同源托管验证 |
| PostgreSQL | PostgreSQL + Spring JDBC | 本机安装/运行方式、驱动版本、事务/备份恢复及空库迁移测试 |
| Flyway | Flyway迁移 | PostgreSQL支持模块匹配、迁移新建/升级/错误中止测试 |
| POI / PDFBox | DOCX/PDF解析 | Java兼容、依赖树、许可证/CVE、约定中文样本与异常样本测试 |
| Spring Security | 单操作者会话/CSRF | 与Boot BOM一致；登录、CSRF、Cookie、会话失效、局域访问保护测试 |
| LangChain4j | Boot 3接入优先候选 | starter与Boot 3.5兼容、MiMo/DeepSeek协议、JSON二次校验、工具限制测试 |

最终版本清单应连同依赖锁文件、验证命令及结果进入设计/运行文档。在线页面当前推荐版本不自动等于本项目应选版本；发现无兼容组合时先回到选型评审，不悄然替换技术方向。
